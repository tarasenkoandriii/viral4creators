## 1. Главный факт, от которого всё зависит

**YouTube Data API не умеет добавлять звуковые дорожки.** В API v3 нет
такого ресурса вообще: есть `captions` (текстовые дорожки), есть
`videos`, `playlists`, `thumbnails` — аудиодорожек нет ни в каком виде.
Мультиязычный звук добавляется **только руками, в YouTube Studio на
десктопе**, и требует включённых Advanced features у канала. Справка
Google говорит прямо: функция не генерирует дубляж сама, «creators will
have to record dubbed audio tracks before uploading».

Проверено 24.09.2026 по списку ресурсов API и справке YouTube — ссылки
в конце документа. **Это не «пока не нашли» и не «надо поискать
обходной путь»: ресурса нет.**

Отсюда решение владельца от 24.09.2026: **один ролик, дорожки руками.**
Продукт делает всё, что можно сделать машиной, и отдаёт оператору
готовые файлы с инструкцией; последний шаг — загрузка дорожек в Studio —
делает человек.

Отвергнутая альтернатива — **отдельный ролик на локаль**. Технически она
сегодня доступна целиком (модуль публикации уже умеет), и рука не
нужна вовсе. Но просмотры, комментарии и рекомендации размазываются по
пяти роликам вместо одного — ровно против этого YouTube и завёл
мультиязычный звук. Один ролик с пятью дорожками собирает метрику в
одну точку; пять роликов конкурируют друг с другом в выдаче.

### 1.1 Что API всё-таки умеет — и это половина задачи

| Возможность | API | Сегодня в продукте |
|---|---|---|
| Локализованные заголовок и описание | `videos.update`, объект `localizations` | нет |
| Язык оригинального текста | `snippet.defaultLanguage` | нет |
| Язык звука оригинала | `snippet.defaultAudioLanguage` | нет |
| Субтитры на каждый язык | `captions.insert` | нет (но `.srt` уже генерируется) |
| Дополнительные звуковые дорожки | **нет такого ресурса** | — |

То есть машиной делается всё, кроме самих дорожек. Это и определяет
порядок этапов: сперва теги (136) — они не ждут никого, потом
локализация, которую API делает сам (137), потом дорогая часть со
звуком (138), потом передача человеку (139).

## 2. Что уже есть в продукте

Проверено по коду 24.09.2026 — это не пожелания, а то, на что можно
опереться.

- **Выгрузка в YouTube** работает: `modules/publishing/youtube-upload.service.ts`,
  resumable-загрузка, идемпотентное восстановление через `checkStatus`,
  связь «наш ролик → `videoId`» в `PublicationRequest.externalId`.
- **Озвучка** — три провайдера (`modules/tts/`): ElevenLabs
  (`eleven_multilingual_v2`), Resemble (локали `uk, ru, en, de, es, fr,
  it, pl`), Veo-заглушка. Синтез возвращает **байты mp3**.
- **Клонирование голоса** — `modules/user-voices/`, модель `UserVoice`,
  всегда Resemble, с обязательным `consentAt`.
- **Переозвучка уже написана** — `POST /sessions/:id/postprod/revoice`:
  пересобирает ролик от `renderedUrl` (исходник провайдера, который
  никогда не удаляется), заново синтезирует голос, субтитры и кроп.
- **Субтитры с реальными таймкодами** — `common/subtitles.ts`,
  `buildSrt()`; готовый `.srt` лежит в нашем Blob
  (`GeneratedVideo.subtitleUrl`). **Но не у всех роликов:**
  `DEFAULT_SUBTITLES_MODE = 'off'`, то есть файл существует, только если
  человек включил субтитры при сборке. Первая редакция этого ТЗ на него
  опиралась как на данность — см. §11, находка 1.
- **Текст озвучки** — `session.generationPrompt.finalVoiceoverScript ??
  .voiceoverScript`.
- **Инпут тегов в мастере УЖЕ ЕСТЬ** — `PublishPanel.tsx`, поле
  редактируемое, уходит в `PublicationRequest.tags` и оттуда в
  `snippet.tags` при загрузке. Но заводится оно пустым
  (`useState('')`), а сервер досыпает к нему только категорию и название
  товара. То есть городить инпут заново не надо — надо дать ему
  осмысленное умолчание.
- **Звук без речи провайдера получить можно двумя путями**, и оба уже
  работают: `voiceMode: 'dub'` выбрасывает дорожку исходника из микса
  целиком, а `silentSource` (Grok с `generate_audio: false`) даёт файл
  вообще без звукового потока.

## 3. Чего нет — и это объём работы

1. **Скоупа `youtube.force-ssl` нет.** Сейчас запрашиваются
   `youtube.upload` и `youtube.readonly`. Ни `captions.insert`, ни
   `videos.update` с локализациями с ними недоступны. **Это самое
   неприятное место всего ТЗ** — см. §4.
2. **При загрузке не ставятся** `defaultLanguage`, `defaultAudioLanguage`,
   `localizations`, `categoryId`. В `part` запроса только
   `snippet,status`.
3. **Переозвучка перезаписывает ролик той же сессии.** Хранения
   нескольких языковых версий одного ролика нет: сделав украинскую
   версию, английскую вы потеряете.
4. **Перевода сценария нет.** Перевод в продукте есть только у блога и
   подсказок мастера.
5. **TTS не возвращает длительность** — только байты и число символов.
   Для §5 это критично. ✅ Закрыто 24.09.2026: длительность меряется по
   байтам (`common/mp3-duration.ts`), см. §5.
6. **Экспорта «полной альтернативной звуковой дорожки»** (музыка +
   переведённый голос, длиной ровно в ролик) нет ни в каком виде.
7. **Теги исходного ролика не собираются вовсе.** Продукт разбирает
   референс с YouTube, но `snippet.tags` не запрашивает: у `search.list`
   берётся `part: 'snippet'` (там тегов нет по устройству API), у
   `videos.list` — `part: 'statistics,contentDetails'`, то есть `snippet`
   не берётся совсем. Метаинформация, про которую говорит владелец,
   сегодня проходит мимо.

## 4. Смена скоупа: только наш канал, и не для всех

`youtube.force-ssl` — новое согласие: Google выдаёт токен ровно с теми
правами, на которые человек согласился, и добавить скоуп задним числом
нельзя.

Первая редакция этого ТЗ делала отсюда вывод «придётся переподключить
каждый канал» и называла это самой неприятной миграцией. **Аудит снял
половину проблемы, а решение владельца — вторую.**

1. **Мультиязычным делается НАШ канал, не клиентские** (решение
   24.09.2026). Значит расширенное согласие нужно ровно одному каналу —
   тому, который подключит оператор.
2. **Просить `force-ssl` у всех подряд нельзя.** Скоуп «жирный»: он даёт
   право не только на субтитры, но и на удаление роликов. Клиенту,
   которому нужна одна загрузка, просить право удалять его ролики — это
   и лишний испуг на экране согласия, и лишний разговор с Google на
   верификации.

Отсюда конструкция: **базовый набор скоупов остаётся как есть**
(`youtube.upload`, `youtube.readonly`) и просится у всех, а расширенный
(`+ force-ssl`) — отдельным действием «подключить расширенно», и только
там, где он нужен. Google умеет это штатно — инкрементальная
авторизация с `include_granted_scopes=true`: человек досогласовывает
недостающее право, не теряя уже выданных.

`PublishingChannel.scopes` уже хранится, поэтому продукт всегда знает,
что именно ему разрешили: канал без `force-ssl` работает ровно как
сегодня — грузит ролики и ничего не теряет, — а рядом с ним стоит
кнопка «разрешить субтитры и переводы описаний» с объяснением, зачем
это и что продукт этим правом делает. Ничего не удаляет.

## 5. Длина дорожки — настоящая трудность этого ТЗ

YouTube требует, чтобы дорожка была **примерно той же длины, что
видео**. А переведённая реплика почти никогда не совпадает по длине с
оригинальной: немецкий длиннее английского процентов на пятнадцать,
украинский и русский тоже расходятся. Восьмисекундный ролик — это
жёсткая рамка, из которой некуда деться.

Поэтому перевод сценария здесь — **не обычный перевод, а перевод под
хронометраж**, и это должно стоять прямо в промпте: сохранить смысл и
уложиться в столько же слогов, а не перевести точно. Плюс три проверки
машиной:

1. **Померить длительность синтезированной дорожки.** ✅ **Сделано
   24.09.2026** — первым кирпичом этапа, до всего остального: без числа
   проверять нечего. `common/mp3-duration.ts` разбирает заголовки кадров
   самих байт (ID3v2, Xing/Info для VBR, счёт кадров для CBR — случай
   обоих провайдеров продукта), `SynthesisResult.durationSeconds`
   заполняют и ElevenLabs, и Resemble. Не ffmpeg: он у продукта хостед,
   то есть платная задача с опросом готовности, — платить job'ом за
   число, лежащее в заголовке первого кадра, плохой размен. «Не смогли
   измерить» — `null`, а не ноль: на нуле проверка длины решила бы, что
   дорожка не годится. Заодно закрыт старый разрыв: шапка `tts.types.ts`
   обещала «текст → mp3 плюс длительность» с самого начала, а поля не
   было.
2. **Уложиться в допуск.** Предлагается ±5 % от длины ролика: больше —
   рассинхрон видно на губах и на монтаже, меньше — недостижимо для
   живого перевода.
3. **Не уложились — не выдавать молча.** Два хода, в таком порядке:
   попросить перевод короче (одна повторная попытка с явным «на N %
   короче»), и только потом растянуть/сжать темп синтеза. Оба записаны в
   карточке дорожки, чтобы оператор видел, что с ней делали.

Дорожка для YouTube — это **полный звук ролика на другом языке**, а не
один голос: она ЗАМЕНЯЕТ оригинальную целиком. Собирать её надо **тем же
рецептом ffmpeg, что и оригинальный звук**, подменив ровно один вход —
файл голоса. Это не то же самое, что «музыка плюс голос»: в режиме
`voiceover` в миксе есть ещё и приглушённая дорожка исходника
(`DEFAULT_DUCK = 0.15`) — атмосфера, шумы, музыка ролика. Собрав
альтернативную дорожку из одной подложки и голоса, мы дали бы зрителю на
немецком заметно более пустой звук, чем зрителю на украинском, и никто
бы этого не заметил до жалоб. Громкости и `loudnorm=I=-16:TP=-1.5:LRA=11`
берутся оттуда же — из `common/postprod.ts`, а не выставляются заново.

## 6. Квоты YouTube: жёсткий потолок, который надо знать заранее

Числа со страницы квот Google на 24.09.2026, и они меняют планирование:

| Вызов | Цена |
|---|---|
| `captions.insert` | **400 единиц** |
| `videos.update` | 50 единиц |
| `videos.list`, `subscriptions.list` | 1 единица |
| `search.list` | **отдельный лимит: 100 вызовов в сутки** |
| Общий пул на всё остальное | **10 000 единиц в сутки** |

Отсюда два следствия, о которых легко забыть и дорого вспомнить.

**Субтитры — самая дорогая операция во всём ТЗ.** Пять языков на ролик
— это 5 × 400 = 2000 единиц, то есть **не больше пяти роликов в сутки**
на полный комплект субтитров, и это если больше ничего не делать.
Локализации по сравнению с ними дёшевы (50 единиц). Значит этап 137
обязан считать бюджет и уметь растягивать работу на несколько суток, а
не падать на шестом ролике. Своего счётчика у продукта уже два —
`BlogYoutubeSearchUsage` и `YoutubeSearchUsage`, приём известный.

**Сотня поисков в сутки — на весь проект, а не на пользователя.** Этот
лимит уже сегодня делят генератор блога
(`BLOG_YOUTUBE_SEARCH_DAILY_LIMIT`, умолчание 10) и поиск референсов
пользователями (`YOUTUBE_SEARCH_DAILY_LIMIT_PER_USER`, умолчание 20 на
человека). Пятеро активных пользователей выбирают сотню за день — и
тогда перестают работать ОБА, причём блог молча, а пользователь видит
пустой поиск. Это находка не этого ТЗ, а его соседа, но всплыла она
здесь, и записать её надо здесь же: **потолки в переменных окружения
сегодня не согласованы с настоящим потолком площадки.**

## 7. Ограничение, о котором нельзя забыть: ролики с голосом Veo

Переозвучка недоступна, когда голос ведёт сама модель: у такого файла
отдельной голосовой дорожки нет, речь запечена в видео. В коде это уже
проверяется и отвечает внятным отказом.

Для мультиязычного ролика это означает жёсткое правило: **кандидат на
мультиязычность — только ролик, собранный с нашим голосом**
(`voiceMode: 'voiceover'` или `'dub'`). Ролик с голосом Veo надо
пересобрать заново, и это не доработка, а новая генерация за деньги.
Экран обязан говорить это до того, как человек нажмёт «сделать
мультиязычным», а не после.

## 8. Модель данных

Одна таблица. Языковая версия ролика — это не сессия и не публикация:
сессия у ролика одна, публикация одна (один `videoId`), а версий звука
столько, сколько языков.

```prisma
/// Звуковая дорожка ролика на одном языке (ТЗ мультиязычного YouTube).
model VideoAudioTrack {
  id        String @id @default(cuid())
  sessionId String
  /// Локаль дорожки. Оригинал строкой НЕ заводится: он и есть сам ролик.
  locale    String
  /// Перевод сценария под хронометраж (§5) — то, что ушло в синтез.
  script    String @db.Text
  /// Локализованные заголовок и описание для `videos.localizations`.
  /// Живут ЗДЕСЬ, а не в `PublicationRequest`: тот — снимок на площадку,
  /// и при повторной заявке переводы потерялись бы. Дорожка и
  /// локализация — одна и та же «языковая версия ролика».
  title       String?
  description String? @db.Text
  /// Готовый звук: музыка + переведённый голос, длиной в ролик.
  audioUrl      String?
  audioPathname String?
  /// Длительность в миллисекундах и расхождение с роликом в процентах —
  /// по ним видно, годится дорожка для YouTube или нет (§5).
  durationMs Int?
  driftPct   Float?
  /// Субтитры на этом языке — тот же .srt, что продукт уже умеет.
  subtitleUrl      String?
  subtitlePathname String?
  status VideoAudioTrackStatus @default(PENDING)
  /// Что с ней делали, чтобы уложиться в длину: сокращали перевод,
  /// меняли темп. Видно оператору, а не выясняется на слух.
  fitNote String?
  errorMessage String?
  /// Оператор подтвердил, что залил её в Studio. Машина этого знать не
  /// может — API дорожек не отдаёт (§1).
  uploadedAt DateTime?
  createdAt  DateTime @default(now())
  updatedAt  DateTime @updatedAt
  @@unique([sessionId, locale])
  @@index([status])
  @@map("video_audio_tracks")
}

enum VideoAudioTrackStatus {
  PENDING    // заведена, ничего не делали
  TRANSLATED // сценарий переведён под хронометраж
  SYNTHESIZED// голос синтезирован
  MIXED      // собран полный звук, длина проверена
  READY      // годится к загрузке
  FAILED     // не уложились или сбой
}
```

`@@unique([sessionId, locale])` — одна дорожка на язык, как и у
приглашений: повторный прогон не плодит дубли.

## 9. Этапы

### Этап 136. Теги: умолчание из исходника и правка человеком ✅ сделано

**Делаем.** Забор `snippet.tags` исходного ролика при разборе референса;
хранение их в сессии; подстановка как умолчания в уже существующий инпут
тегов мастера (`PublishPanel`); запасной источник тегов, когда у
исходника их нет; те же теги во всех заявках на публикацию, с правкой
пользователем перед отправкой.

**Зачем первым.** Это единственный этап ТЗ, который **не упирается ни во
что внешнее**: ни в верификацию Google, ни в новый скоуп, ни в квоту
субтитров. Теги уже уезжают в `snippet.tags` при загрузке, инпут уже
есть и уже редактируемый — не хватает ровно умолчания. И это
единственный этап ТЗ, который достаётся клиентам, а не только нашему
каналу.

**Что конкретно менять.** У `videos.list` сейчас запрашивается
`part: 'statistics,contentDetails'` — надо добавить `snippet` и взять
оттуда `tags`. У `search.list` тегов нет по устройству API, и это не
обойти: `search.list` вообще не отдаёт полный `snippet`. Значит теги
приходят на том шаге, где продукт и так дочитывает ролик по id.

**Запасной источник — обязателен, а не «на будущее».** Тегов у исходника
может не быть по трём причинам сразу: автор их не заполнил; референс
пришёл файлом, а не ссылкой на YouTube; API их не отдал (см. открытый
вопрос ниже). Во всех трёх случаях инпут не должен оставаться пустым —
умолчание собирается из того, что продукт про ролик и так знает:
название товара, категория, язык реплик. Сегодня сервер досыпает
категорию и название уже сейчас, надо лишь показать их человеку ДО
отправки, а не после.

**Открытый вопрос — закрыт документацией, но не живым вызовом.** Отдаёт
ли `videos.list` `snippet.tags` для ЧУЖОГО ролика или только владельцу:
справка Google помечает ограничением владельца ровно шесть мест
(`contentDetails.hasCustomThumbnail`, `statistics.dislikeCount`,
`fileDetails`, `processingDetails`, `suggestions`, `snippet.localized`)
— `snippet.tags` среди них нет. Живой вызов с нашим `YOUTUBE_API_KEY`
из песочницы сделать нечем, и это осталось непроверенным: ключа у меня
нет и просить его я не буду. Риск при этом нулевой ровно потому, что
запасной источник сделан обязательным, а не «на будущее»: если теги
придут пустыми, поле всё равно заполнено, просто названием товара и
категорией. **Проверяется за минуту** — зарегистрировать ссылку на
чужой ролик с заполненными тегами и посмотреть, что подставилось в поле
публикации.

**Решение, которое стоит принять сразу: теги не переводятся.** У ролика
на YouTube один общий список тегов, локализовать его нечем — в
`localizations` только заголовок и описание. Для мультиязычного канала
это значит, что теги стоит держать смешанными (ключевые слова на языке
оригинала плюс английские), а не переводить под каждую локаль. Этап 137
на них не влияет.

**Зависимости.** Нет. Может делаться первым и отдельно от всего
остального ТЗ.

**Приёмка.** Ролик, собранный по ссылке на YouTube, открывает панель
публикации с уже заполненными тегами исходника; человек их правит, и
уходит именно правленое; ролик без тегов у исходника всё равно
показывает осмысленное умолчание, а не пустое поле; повторная заявка на
вторую площадку берёт те же теги; правка тегов не трогает ничего, кроме
тегов.

**Размер.** Маленький.
**Риск.** Низкий. Единственное неизвестное — видимость `snippet.tags`, и
оно снимается до начала работы.

**Сделано (24.09.2026).** `parseYoutubeVideoId` (разбор ссылки в id,
свой модуль с тестами); `YoutubeSearchService.fetchVideoTags` —
отдельный `videos.list` с `part: 'snippet'`; `registerYoutubeVideo`
зовёт его и кладёт `sourceTags` в `originalVideo` сессии;
`frontend/src/lib/publish-tags.ts` — чистое правило умолчания и разбор
поля; `PublishPanel` показывает умолчание в уже существовавшем инпуте;
`snapshotFromSession` перестал досыпать своё поверх присланного. В
журнале расходов (§26) появилась своя строка — операция `video-tags`.

**Четыре решения, которые стоит знать.**

1. **Теги берутся при регистрации ссылки, а не в поиске.** В поиске их
   пришлось бы тащить для пятидесяти строк таблицы, из которых нужна
   одна, — и всё равно остался бы непокрытым второй путь, где ссылку
   вставляют руками, минуя поиск. Регистрация — единственная точка,
   общая для обоих путей. Цена: одна единица квоты Google на
   регистрацию против ста у поиска.
2. **Суточный слот поиска этот вызов не занимает.** По той же причине,
   по которой его не занимает `videos.list` за статистикой: он случается
   не по отдельной команде человека, а внутри уже начатого действия.
   Иначе человек терял бы поиски за то, что выбрал ролик.
3. **Сервер больше не досыпает категорию и название к присланным
   тегам.** Это и было главной правкой этапа, и она не про теги, а про
   доверие: раньше убранный в панели тег молча возвращался обратно уже
   ПОСЛЕ отправки — правка человека отменялась там, где её нельзя было
   увидеть. Теперь то же умолчание показано ДО отправки, в поле ввода, и
   решает человек. Запасной источник при этом никуда не делся: заявка
   вообще без тегов (старый клиент, вызов из админки) получает прежнее
   умолчание, и пустым список тегов по-прежнему не бывает.
4. **Регистрация референса не может сломаться из-за тегов.** Их запрос
   не бросает наружу ничего сам и дополнительно обёрнут `catch` на
   стороне вызывающего — «референс регистрируется, даже если тегов не
   досталось» инвариант регистрации, и держать его на честном слове
   соседнего класса нельзя. Проверено тестом: мутация, снимающая
   страховку, падает.

**Чего этап НЕ делает.** Теги не переводятся (решение выше) и не
перечитываются: `sourceTags` — снимок на момент регистрации, а не
зеркало YouTube. Умолчание считается один раз, при первом показе
панели, и больше никогда не трогает правку человека.

### Этап 137. Локализация публикации: то, что API делает само ✅ сделано

**Делаем.** Скоуп `youtube.force-ssl` и переподключение каналов (§4);
`snippet.defaultLanguage`, `defaultAudioLanguage` **и `categoryId`** при
загрузке; локализованные заголовок и описание через `videos.update` с
`localizations`; загрузка субтитров через `captions.insert`; перевод
заголовка и описания на пять локалей тем же механизмом, что переводит
блог (xAI Grok Batch).

**Три вещи, на которых этот этап сломается, если сделать наивно** (все
три — находки аудита, §11):

1. **Обновление стирает то, чего нет в запросе.** Перед `videos.update`
   ролик читается целиком, и `snippet` собирается из прочитанного плюс
   новые поля — а не из наших снимков. Иначе теги и описание исчезнут.
2. **`categoryId` обязателен при обновлении `snippet`,** а продукт его
   не ставит нигде. Значит он появляется на этапе 137 и при загрузке
   тоже — иначе первое же обновление упрётся в обязательное поле.
3. **Локализации требуют заданного `defaultLanguage`** (иначе
   `defaultLanguageNotSet`), то есть язык оригинала ставится раньше
   переводов, а не вместе с ними.

Субтитры: у ролика, собранного без них (`DEFAULT_SUBTITLES_MODE = 'off'`
— это умолчание), `.srt` не существует, и его надо сгенерировать
имеющимся `buildSubtitles`. «Уже готово» — только для тех, у кого
субтитры включали.

**Зачем вторым.** Здесь нет ни одного ручного шага и нет трудности с
длиной. Канал становится мультиязычным по тексту в тот же день, и по
данным видно, даёт ли локализация прирост, — до того как вкладываться в
звук.

**Приёмка.** У опубликованного ролика в YouTube Studio видны пять
вариантов заголовка и описания; субтитры оригинального языка загружены
и включаются на плеере; **теги и описание после обновления локализаций
на месте** (проверяется явно — это находка 2, и она молчаливая); канал
со старым грантом честно помечен «нужно переподключить» и продолжает
грузить ролики как раньше; ролик, у которого локализации не удались,
всё равно опубликован — локализация не обязана ронять публикацию.

**Риск.** Верификация приложения в Google из-за `force-ssl`. Начинать
надо с неё, а не с кода.

**Сделано (24.09.2026) — и этап оказался вдвое дешевле, чем написан.**

Проверка документации перед кодом (та самая, которой не хватило первой
редакции) показала главное: **`videos.insert` принимает
`part=localizations` и работает с уже имеющимся скоупом
`youtube.upload`.** `force-ssl` нужен только `videos.update` и
`captions.insert`. Значит локализованные заголовки и описания ставятся
**в момент загрузки, одним запросом**, и вместе с этим отпадают:

- верификация приложения в Google и переподключение канала — для
  текстовой локализации они не нужны вовсе;
- находка 1 (обновление стирает то, чего нет в запросе) — стирать
  нечего, ролика ещё нет;
- находка 2 в её страшной части (`categoryId` обязателен при обновлении
  `snippet`) — `categoryId` всё равно ставится, но теперь как обычное
  поле при загрузке, а не как условие второго прохода.

Осталась на месте только находка 3: **без `snippet.defaultLanguage`
площадка отвергает локализации целиком**, поэтому язык ролика теперь
часть снимка заявки (колонка `publication_requests.language`, миграция
92, берётся из локали сессии) и уезжает и в `defaultLanguage`, и в
`defaultAudioLanguage`. Снимком, а не ссылкой на сессию, по той же
причине, что и заголовок рядом: заявка переживает TTL сессии.

**Что именно сделано.** `categoryId` (22 — «People & Blogs», константой:
канал у продукта один), `defaultLanguage`/`defaultAudioLanguage` и
`localizations` при загрузке; перевод заголовка и описания на остальные
четыре локали — `PublicationTranslationService` с чистым модулем
промпта и разбора рядом (`publication-translation.ts`), по образцу
`analysis-translation.ts` этапа 59.

**Одно отступление от буквы ТЗ, сознательное: перевод синхронный, а не
через Grok Batch.** Для статьи блога пачка верна — перевод не срочный и
вдвое дешевле. Здесь наоборот: локализации нужны В МОМЕНТ загрузки,
тем же запросом, что и `snippet`, а пачка приходит часами позже, когда
ролик уже опубликован. Пришлось бы городить второй проход
`videos.update` — ровно тот, ради которого понадобился бы `force-ssl`,
которого нет. Один короткий текстовый вызов на ролик; прецедент в
продукте уже есть.

**Локализация не роняет публикацию** — ни отказом провайдера, ни
мусором в ответе, ни отсутствующим ключом: во всех случаях пустая карта
и ролик без локализаций. Проверено тестом и мутацией, снимающей
страховку. Возобновлённая сессия загрузки за переводом не ходит
повторно: у неё `snippet` площадкой уже принят, и второй вызов был бы
деньгами на ветер.

**Субтитры — сделаны 24.09.2026, третьим проходом.** Это единственное
место всего ТЗ, которому нужен скоуп `force-ssl`.

- **`.srt` собирается из реплик при постановке в очередь, а не берётся
  файлом.** У ролика с выключенными субтитрами (`DEFAULT_SUBTITLES_MODE
  = 'off'` — умолчание) файла не существует вовсе, но для площадки
  субтитры это просто текст с таймкодами: ffmpeg для него не нужен,
  нужен тот же `buildSrt`, что и для прожига. Текст ложится в снимок
  заявки (миграция 97) рядом с заголовком и описанием — по той же
  причине, что и язык: заявка переживает TTL сессии.
- **Тайминг эвристический**, по длине реплик: настоящее пословное
  выравнивание живёт внутри синтеза озвучки и до заявки не доезжает.
  Дрейф в доли секунды на восьмисекундном ролике зритель не заметит, а
  субтитров иначе не будет вовсе.
- **Загрузка идёт ПОСЛЕ публикации и лучшей попыткой.** Отказ площадки
  по субтитрам не возвращает заявку в очередь: ролик уже на канале, и
  повторная попытка залила бы его второй раз. Причина пишется в заявку —
  чтобы «субтитров нет» имело ответ в базе, а не только в логе.
- **У канала без расширенного согласия шаг просто не делается**, и это
  тоже записано причиной. Ролик опубликован, заголовок и описание на
  месте, а на экране каналов стоит кнопка «Разрешить субтитры».
- **Формат запроса собирается руками** (`multipart/related`, две части,
  разделитель CRLF, `isDraft: false`) — без SDK, той же конвенцией, что
  у остальных клиентов площадок. Ошибиться здесь легче всего: площадка
  отвечает 400 без подробностей, поэтому у тела запроса свой тест.

**Осталось владельцу:** верификация приложения в Google под скоуп
`force-ssl` и одно нажатие «Разрешить субтитры» на экране каналов. До
этого продукт работает как работал — просто без субтитров.

**Расширенное согласие сделано (24.09.2026) — вторым проходом.** Это та
часть приёмки, которая звучит как «канал со старым грантом честно
помечен „нужно переподключить“ и продолжает грузить ролики как раньше»,
и она не ждёт ни Google, ни субтитров: без неё нельзя даже начать
разговор с Google, потому что нечего показать на проверке.

- Скоупы разделены на базовый набор (`youtube.upload`,
  `youtube.readonly` — просится у всех) и расширенный
  (`+ youtube.force-ssl` — отдельным действием и только для YouTube).
  Расширение НЕ теряет базовых прав: канал, умевший грузить ролики,
  обязан уметь это и после. Закреплено тестом — потеря была бы молчаливой
  и обнаружилась бы первой же неудавшейся выгрузкой.
- `include_granted_scopes=true` — инкрементальная авторизация Google:
  человек досогласовывает недостающее право, не теряя уже выданных.
- `PublishingChannelView.captionsAllowed` — ответ на вопрос «что этому
  каналу разрешено», считается из `scopes`, которые продукт и так хранит.
  Токены наружу по-прежнему не уходят.
- На экране каналов у YouTube-канала без права — объяснение и кнопка
  «Разрешить субтитры», с прямой фразой о том, что продукт этим правом
  делает и чего не делает (не удаляет). У канала с правом — строка о том,
  что субтитры разрешены. Пять локалей.
- Просьба о расширенном согласии для TikTok — явный отказ, а не тихая
  обычная ссылка: такого согласия у площадки нет вовсе, и молча выдать
  обычную значило бы пообещать право, которого человек не получит.

### Этап 138. Альтернативные звуковые дорожки ✅ сделано

**Делаем.** `VideoAudioTrack`; перевод сценария под хронометраж (§5);
синтез на каждую локаль существующим TTS; сборка полного звука тем же
рецептом ffmpeg, что у оригинала, с подменой одного входа — файла голоса
(§5); замер длительности и допуск ±5 % с одной повторной попыткой
сократить перевод; субтитры на каждый язык из переведённого сценария.

**Открытый вопрос, который надо снять ДО этапа.** Клонированный голос
обучен на образце одного языка. Заговорит ли он на четырёх остальных и
не поедет ли акцент — **не проверено**, а от ответа зависит, ради чего
всё затевалось. Проверяется одним живым прогоном Resemble, и сделать это
надо раньше, чем писать код. Если кросс-язычный клон не работает —
дорожки собираются штатным голосом провайдера, и это надо честно
написать на экране, а не выдавать чужой голос за голос владельца.

**Зависимости.** 137 (иначе субтитры некуда грузить).

**Приёмка.** Для ролика с нашим голосом собираются четыре дорожки,
каждая в пределах допуска; расхождение и то, чем его лечили, видно в
карточке; ролик с голосом Veo отвечает внятным отказом ДО списания
денег; повторный прогон не плодит дубли и не тратит синтез второй раз.

**Риск.** Длина. Если окажется, что допуск в 5 % недостижим на живых
текстах, лечится он числом — допуск или лимит слогов в промпте, — а не
переписыванием этапа.

**Сделано 24.09.2026 — весь этап, кроме передачи файлов оператору
(этап 139) и субтитров на каждый язык (этап 141).** Перевод под
хронометраж, синтез, измерение, решение и сборка полного звука.

- **`common/audio-track-fit.ts`** — правила §5, и по дороге уточнилась
  сама постановка. ТЗ говорит «дорожка не совпадает по длине с видео»,
  но в продукте длина готовой дорожки равна длине ролика САМА: рецепт
  `common/postprod.ts` приводит подложку к длине ролика и микширует с
  `duration=first`. Ломается другое — **длинная реплика не удлиняет
  дорожку, а обрывается на полуслове**, и зритель на немецком слышит
  фразу, которая кончилась ничем. Поэтому проверки считают не длину
  файла, а укладывается ли РЕЧЬ в ролик вместе со своим сдвигом от
  начала. Недобор дефектом не считается вовсе: тишина в хвосте штатна,
  под ней играет подложка.
- **Порядок ходов ровно из ТЗ:** перевод короче (один раз, с явным «на
  N процентов» и прошлым вариантом в промпте) → подгонка темпа →
  человеку с причиной. Предел подгонки — 10 %: прежнее решение продукта
  отказалось от `atempo` словами «ускорить на 20 % звучит как
  испорченная запись»; здесь оно не отменяется, а уточняется — у
  альтернативной дорожки текста «под восемь секунд» не бывает, он задан
  оригиналом.
- **Подгонка темпа применяется ПРИ СБОРКЕ, а не отдельным проходом:**
  сборка и так задача ffmpeg, и `atempo` там — ещё один фильтр в том же
  вызове, а не второй счёт.
- **`track-translation.ts`** — промпт, где требование длины стоит первым
  и меряется в слогах, а не в символах: слогами меряется произносимая
  длина, а символы у кириллицы и латиницы считаются по-разному.
- **`VideoAudioTrack`** (миграция 93) — одна строка на язык, с
  измеренной длиной, перебором, нужным ускорением и причиной на
  человеческом языке. `sessionId` без внешнего ключа: дорожка переживает
  TTL сессии, как и заявка на публикацию.
- **Ход сокращения расходуется, даже если второй перевод не удался** —
  иначе следующий прогон снова пойдёт просить короче и снова заплатит за
  то же самое.

**Сборка полного звука — вторая половина того же дня.**

- **Рецепт звука вынесен в одно место** (`audioMixFilters` в
  `common/postprod.ts`) и зовётся обеими сборками. Это буквальное
  прочтение ТЗ «тем же рецептом, подменив ровно один вход»: собери
  дорожку отдельно «из музыки и голоса», и зритель на немецком получил
  бы заметно более пустой звук, чем зритель на украинском — в миксе
  `voiceover` есть ещё и приглушённая дорожка самого ролика, атмосфера и
  шумы. Заметить это было бы некому до жалоб, поэтому сравнение двух
  команд стоит отдельным тестом.
- **Вход `source` — ИСХОДНЫЙ рендер, а не готовый ролик.** В готовом уже
  звучит оригинальный голос, и новая речь легла бы поверх него.
- **Три отличия от обычной сборки, и все вынужденные:** на выходе только
  звук (`-vn` — самая дорогая часть обычной задачи, перекодирование
  картинки, здесь не нужна вовсе); `atempo` тем же вызовом, а не вторым
  проходом; длина гарантируется с обеих сторон (`apad` тянет короткий
  микс, `-t` режет длинный) — у обычной сборки длину держит видеопоток,
  здесь его нет.
- **Сборка оплачивается только у дорожки, которая влезла.** У ушедшей
  человеку — сначала решение человека: он может поправить реплику
  руками, и платить заранее значило бы платить дважды.
- **Задача асинхронная**, как и постобработка ролика: `mixJobId` рядом с
  готовым файлом, `pollMix` дозабирает. Отдельного статуса «собирается»
  нет намеренно — «задача есть, файла нет» означает то же самое, а
  добавление значения в enum Postgres внутри миграции это отдельная
  головная боль. Сетевая икота опроса задачу не гасит: она уже
  оплачена.

### Этап 139. Передача оператору ✅ сделано

**Экран живёт в АДМИНКЕ, и это следствие решения о канале.**
Мультиязычным делается наш собственный канал, значит в Studio заходит
наш же оператор — человек, у которого доступ есть. Была бы речь о
клиентских каналах, этот этап пришлось бы писать заново и вдвое
больше: файлы и инструкция жили бы в мини-аппе, а объяснять Studio
пришлось бы человеку, который о нём не слышал (находка 7 аудита, §11).

**Делаем.** Экран ролика в админке: список дорожек, кнопка «скачать
все», краткая инструкция для Studio (Languages → Add language →
загрузить файл), отметка «залито» на каждую дорожку с датой;
предупреждение про Advanced features; напоминание из справки Google —
если у языка уже есть автодубляж YouTube, его надо удалить перед
загрузкой своей дорожки.

**Зависимости.** 138.

**Приёмка.** Оператор проходит путь «открыл ролик → скачал четыре файла
→ загрузил в Studio → отметил» без чтения этого документа; отметка
переживает перезагрузку; неотмеченные дорожки видны списком, чтобы
работа не терялась.

**Почему отметку ставит человек.** API дорожек не отдаёт (§1) —
проверить машиной, что дорожка залита, нельзя ничем. Отметка оператора
— честная замена, и она честно называется отметкой, а не проверкой.

**Сделано 24.09.2026.** Панель на странице ролика в админке, а не
отдельная вкладка: оператор приходит туда, уже открыв нужный ролик.

- **Инструкция для Studio стоит на самом экране** — четыре шага, а не
  ссылка на документ: приёмка требует пройти путь «не читая этого
  документа».
- **Два предупреждения не декоративные.** Без Advanced features раздела
  «Языки» в Studio не будет вовсе, и человек решит, что сломан продукт;
  а если YouTube уже озвучил ролик автодубляжом, свою дорожку на тот же
  язык он не примет, пока автодубляж не удалён. Оба — из справки Google,
  оба стоят до кнопок, а не после.
- **Причина всегда рядом с состоянием.** «Нужна правка» без объяснения
  — тупик для оператора, поэтому в той же ячейке лежит и `note` (что
  сделали с длиной), и `mixError` (почему не собралось).
- **Отметку нельзя поставить дорожке, которой нет файла** — кнопка
  выключена: отметить «залито» то, чего не скачивал, можно только по
  ошибке. Снятие стирает и дату, и того, кто отметил: «залил Иван, но не
  залил» — это не история, а мусор.
- **Список сам дозабирает завершившиеся сборки** (миграция 94: «задача
  есть, файла нет» = «собирается»). Отдельного крона для этого нет
  намеренно: дорожек в сутки единицы, а экран открывает тот же человек,
  который их ждёт, — дешевле дозабрать в момент открытия, чем будить
  крон каждые две минуты ради пустого прогона.
- **Пересборка не трогает залитые дорожки** (миграция 95): подменить
  файл под отметкой значит оставить оператора в уверенности, что залито
  именно это.

### Этап 141. Субтитры к альтернативным дорожкам ✅ сделано

Последний невыполненный пункт «Делаем» этапа 138 — «субтитры на каждый
язык из переведённого сценария». Сделан 24.09.2026.

**Почему он не делался вместе с дорожкой.** Потому что делать его было
не из чего. Перевод просил у модели «одну строку простой речи» и брал
из ответа первую строку — то есть склеивал реплику из двух-трёх битов
ролика в одну фразу. Тайминг субтитра берётся из разметки реплик
(`heuristicCueTimings`), а к склейке привязывать нечего: получилась бы
одна простыня на весь ролик. Так что этап начинается не с субтитров, а
с перевода.

**Перевод стал построчным.** Строки нумеруются, модель отвечает тем же
числом строк в том же порядке, ответ разбирается ПО НОМЕРАМ, а не по
порядку строк: пояснения («24 syllables») модель дописывает снизу, и
без номеров они встали бы на место реплики. Чужой номер («3.» при двух
битах) отбрасывается — это приписка, а не реплика. Повторённый номер и
неполный набор откатывают разбор к прежнему поведению: одна склеенная
строка. Монеткой выбирать, какой из двух вариантов модель считает
ответом, хуже, чем честно потерять разбивку.

**Это чинит и сам звук, не только субтитры.** Склеенная реплика
произносилась одной фразой без пауз: немецкий голос выговаривал всё к
середине ролика, а картинка шла дальше. Пауза между битами — это часть
хронометража, и она возвращается вместе со строками.

**Тайминг берётся у самой речи — см. аудит этапа ниже.** Первая
редакция раскладывала перевод по секундам оригинала и тянула последний
субтитр до конца ролика; аудит показал, что обе половины неверны.

**`.srt` лежит в строке дорожки** (миграция 98), а не считается при
чтении: дорожка переживает TTL-очистку сессий, а сессия — источник и
сценария, и длины ролика. Считать на лету значило бы потерять субтитр
ровно тогда, когда оператор до него дойдёт. Та же причина, по которой
рядом уже лежит `speech`.

**Отдаётся оператору файлом, а не через API.** `captions.insert` умеет
чужой язык и мог бы залить субтитр сам — но стоит 400 единиц из 10 000
в сутки на весь проект (§6), а главное, толку от переведённого
субтитра без переведённой дорожки немного: это две половины одного
языка, и вторая всё равно идёт руками (§этап 139 — API звуковых
дорожек у YouTube нет вовсе). Поэтому `.srt` скачивается из той же
строки того же экрана, а в инструкции для Studio появился отдельный
шаг.

## 10. Вопрос, который мог обнулить весь замысел — снят

Штатный ролик продукта — **восемь секунд** (`VIDEO_DURATION_SECONDS`),
то есть Shorts. Поддерживает ли YouTube мультиязычный звук для Shorts,
первая редакция не знала, и от ответа зависели оба самых дорогих этапа
ТЗ.

**Ответ положительный, и он в справке Google дословно** (проверено
24.09.2026): «The Multi-language audio feature allows you to upload
audio tracks in different languages to a single video **or Short**».
Условий два, и оба уже были записаны в §1.1: доступ к Advanced features
у канала и «файл примерно той же длины, что видео» — то есть трудность
этапа 138 остаётся ровно та, что описана в §5, и ни одной новой не
добавляется.

Что это значит для плана: этапы 138–139 остаются в силе для штатного
восьмисекундного ролика, а не только для длинных. Проверять в Studio
больше нечего — но при первой же реальной загрузке дорожки стоит
убедиться, что у канала включены Advanced features: без них раздела
Languages не будет, и это будет выглядеть как «функция не работает».

### Второй открытый вопрос — про клонированный голос — переформулирован

Заговорит ли клонированный голос на остальных четырёх языках, живой
проверкой не снято: у клонирования в продукте свой провайдер
(Resemble, `user-voices.service.ts`), и его документация ответа на этот
вопрос в открытом виде не даёт — нужен прогон на своём ключе.

Но **для этапов 138–139 это перестало быть блокером**, и вот почему:
мультиязычным делается НАШ собственный канал (решение владельца), а
озвучка по умолчанию идёт не клонированным голосом, а библиотечным —
через `eleven_multilingual_v2` (`modules/tts/elevenlabs.service.ts`),
модель, которая мультиязычна по устройству и уже используется продуктом
для украинского и русского. Тот же `voice_id` синтезирует и на
остальных языках.

Клонированный голос остаётся вопросом того дня, когда дорожки
понадобятся КЛИЕНТАМ с их собственными голосами, — и тогда его надо
снимать прогоном, а не документацией.

### Вторая редакция — четыре находки, и первая из них меняла этап целиком

7. **Не было сказано, ЧЕЙ это канал.** Весь этап передачи файлов

### Аудит этапа 136 — три находки, все закрыты

Проведён по коду сразу после реализации, 24.09.2026. Все три — про то,
что умолчание из исходного ролика ведёт себя не как два коротких
значения, которые сервер складывал раньше.

1. **Потолок YouTube на теги — 500 символов на ВЕСЬ список, и умолчание
   из исходника пробивает его легко.** До этапа потолок был
   недостижим: список собирался из категории и названия товара. Авторы
   набивают теги десятками, тридцать штук по двадцать символов — уже
   600, и заявка уехала бы в YouTube за ошибкой `invalidTags`: падала бы
   публикация, а не тег. Потолок теперь считается по одним и тем же
   правилам на сервере (`uniqueTags`) и в поле ввода
   (`lib/publish-tags.ts`), включая кавычки, которые YouTube ставит
   вокруг тега с пробелом и считает в те же 500. Берётся с начала,
   пока влезает: выборочно выпавшую середину человек в поле не объяснит.

2. **«Сделать такой же» отдавал ролик без тегов.** Сессия живёт по TTL,
   а публичная кнопка на странице шеринга (§40) собирает новую сессию не
   из живого ролика, а из строки библиотеки разборов — и тегов в той
   строке не было. Спросить их у Google на этом пути **нельзя**: он
   публичный, бесплатный и рядом с рейт-лимитом в тридцать сессий в
   минуту с адреса, то есть платный вызов в нём выел бы суточную квоту
   всего деплоя за час. Поэтому теги переезжают колонкой
   `analysis_library.sourceTags` (миграция 91) — по тому же принципу,
   по которому там уже лежит `aspectRatio`: разбор кладёт их вместе с
   собой, «Сделать такой же» забирает оттуда. У записей, разобранных до
   этапа, колонка пуста, и там работает запасной источник.

3. **Регистрация ссылки перестала быть бесплатной для нас — и осталась
   неограниченной для чужого.** Теперь она тратит единицу суточной
   квоты (10 000 на всё: поиск референсов, блог, теги), а маршрут
   доступен любому, у кого есть id собственной сессии: перебор выел бы
   квоту за минуты и выключил бы YouTube-поиск всем. Это ровно тот
   случай, для которого в проекте заведён `RateLimitGuard`
   («дёшево для нас, неограниченно для чужого»), — поставлены два окна,
   20/мин и 200/час на адрес. Плюс повторная регистрация ТОЙ ЖЕ ссылки
   тегов больше не перечитывает: это снимок, а не зеркало, и второй
   вызов дал бы то же самое за ещё одну единицу. Сам декоратор
   сторожится тестом: исчезнуть при рефакторинге он может молча, не
   уронив ни одной другой проверки.

### Аудит этапа 137 — три находки, все закрыты

Проведён по коду сразу после реализации, 24.09.2026. Общее у всех трёх:
ни одна не видна глазами и ни одна не сломала бы ни одного теста —
локализации просто тихо не появлялись бы, а в худшем случае вместе с
ними не появлялись бы и сами публикации.

1. **Модель была зашита строкой — и именно той, которую Google уже

   требованием «ответь нумерованными строками» — то есть образец
   противоречил форме ответа. Теперь он нумеруется тоже.

### Этап 148. Те же дорожки — владельцу ролика ✅ сделано (бэкенд)

TODO §III п.12 («Локализация одного ролика на N языков») оказался не
новой работой, а доступом: механизм этапов 138–141 — перевод реплики
под хронометраж, синтез, сборка полного звука, субтитры — делает ровно
то, что там описано. Он был admin-only, потому что мультиязычным
делался НАШ канал.

**Открыть его пользователю — не значит снять `@UseGuards`.** У
оператора доступ ко всем сессиям по должности, и `AudioTrackService`
писался под него: он записывает израсходованное, но потолок расхода НЕ
проверяет. Для доверенного человека это верно; для пользователя —
дыра, потому что каждая дорожка это перевод, синтез и задача ffmpeg,
то есть настоящие деньги за каждый язык. Поэтому у пользовательского
входа три проверки, которых нет у операторского:

- **владелец** — чужой ролик отвечает «не найден», а не «нельзя»: по
  ответу нельзя узнать, существует ли чужой ролик с таким номером;
- **тариф** — `multilingualTracks`, Premium, и проверяется раньше
  денег: отказ по тарифу не должен зависеть от того, сколько человек
  потратил сегодня;
- **потолок расхода** — до платной работы, с проектом ролика (от него
  зависит сценарий тестового доступа).

Сверху — ограничитель частоты на сборку (10 за десять минут): суточный
потолок один защищает плохо, его можно выбрать за минуту.

**Список читается и без Premium.** Платного в нём ничего нет, а
человек, у которого дорожки уже собраны, не должен терять к ним доступ
при смене режима.

**Заливает всё равно человек.** API звуковых дорожек у YouTube нет
вовсе (этап 139): пользователь получает готовые файлы и заливает их в
Studio сам, как наш оператор. Обещать здесь автоматику значило бы
обещать чужой API, которого нет.

**Экран.** `AudioTracksPanel` на экране готового ролика
(`#/postprod/:sessionId`), рядом с экспортом, поверх тех же `GET` и
`POST` на `/sessions/:id/audio-tracks`.

Почему панель, а не шаг мастера: дорожки заказывают ПОСЛЕ готового
ролика и не обязательно в тот же день — человек снял, выложил, через
неделю решил выйти на немецкий рынок. Шаг мастера такой сценарий не
обслуживает вовсе.

Решения экрана, которых нет у оператора:

- **Свой опрос, и реже, чем у экспорта — раз в десять секунд.** `GET`
  здесь не просто читает базу: он дозабирает готовые сборки, дёргая
  чужой ffmpeg-сервис по каждой незавершённой дорожке. Пятисекундный
  тик `ExportPanel` означал бы до четырёх чужих запросов каждые пять
  секунд на каждое открытое окно.
- **Флаг остановки у опроса.** У `ExportPanel` его нет, и это дыра,
  которую здесь повторять нельзя: `schedulePoll`, вызванный из уже
  улетевшего запроса, ставит новый таймер ПОСЛЕ размонтирования — то
  есть закрытая панель продолжает дёргать ffmpeg до перезагрузки
  страницы. У экспорта это опрос своей же базы, здесь — чужой сервис.
- **«Собрать недостающие» просит подтверждения поимённо.** Сервер
  собирает по одной дорожке за запрос, значит кнопка — это N запросов
  подряд, то есть N списаний с одного касания. Диалог называет языки и
  говорит, что операция платная.
- **Язык, сборка которого уже идёт, из предложений убран.** Сервер
  честно считает его недостающим: «задача есть, файла нет» для него
  неотличимо от «файла нет вовсе». Оператору это безразлично, а здесь
  рядом оказались бы строка «собирается» и кнопка «Собрать» на тот же
  язык — и «собрать недостающие» оплатила бы вторую сборку того же.
- **Устаревшая дорожка не даёт скачать ни звук, ни субтитры.** Файлы
  на месте и выглядят исправными, но размечены по хронометражу прежней
  версии ролика: залитые к новой, они разъедутся с картинкой, и узнает
  об этом человек от зрителей. Голос при этом тоже закрыт — он от того
  же прежнего ролика.
- **Голос без сборки скачать можно.** Речь синтезирована, не удалась
  только сборка: человек сведёт звук сам, а не будет ждать нашего
  ffmpeg.
- **Панель заканчивается инструкцией для Studio, а не кнопкой
  «опубликовать».** Три шага и предупреждение про Advanced features и
  автодубляж. Кнопки быть не может: API дорожек у YouTube нет.

**Аудит бэкенда — три находки, все закрыты.**

1. **Незнакомый язык в адресе собирал и оплачивал русскую дорожку.**
   `normalizeLocale` возвращает умолчание на любой мусор — это верно
   там, где локаль подсказка интерфейса, и неверно там, где она заказ
   за деньги: у ролика с украинским оригиналом опечатка в адресе
   прошла бы проверку «это не язык оригинала» и собрала бы дорожку,
   которую никто не просил. Ровно эту ошибку нашёл аудит этапа 147 в
   поле `locale` внешнего API — и она повторилась этапом позже, в
   месте, где стоит денег. Теперь незнакомый язык — `400`.

2. **Ограничитель частоты считал по адресу.** Он и добавлялся ради
   денег, а деньги считаются по человеку. В мини-аппе за одним адресом
   сидит сотовый оператор: экран собирает до четырёх локалей подряд, и
   двое соседей по NAT выбрали бы чужое окно, не сделав ничего дурного,
   — а тому, от кого лимит защищает, сменить адрес ничего не стоит.
   `RateLimitRule` получил `by: 'user'`; безымянный запрос
   по-прежнему считается по адресу, иначе все анонимные сложились бы в
   одно окно и первый гость закрыл бы вход остальным.

3. **Дозабор сборок шёл по очереди.** У оператора список открывают раз
   в несколько минут, а экран пользователя будет опрашивать его
   постоянно: четыре опроса чужого ffmpeg подряд на каждом тике — это
   секунды ожидания там, где их никто не ждёт. Поведение перенесено из
   admin-сервиса без правки; теперь параллельно.

**Аудит экрана — шесть находок, все закрыты.** Две первые — одна и та
же ошибка через разные двери, и обе стоили ровно того, ради чего
писалось решение «список читается без Premium».

1. **А-1. Замок закрывал не сборку, а просмотр.** Без Premium панель
   показывала замок вместо уже собранных дорожек — то есть человек,
   понизивший режим, терял доступ к тому, за что уже заплатил. Сервер
   специально отдаёт список без проверки права; экран эту гарантию
   отменял. Теперь без Premium видны и дорожки, и их файлы, а замок
   стоит на месте кнопок сборки.

2. **А-6. Упавшая матрица режимов прятала панель целиком.** `loading` у
   `useFeature` — это `state === null`, а состояние остаётся `null` и
   когда `GET /me/plan` НЕ ЗАГРУЗИЛСЯ: отличить одно от другого по
   этому полю нельзя, ради чего в контексте и появился `error` (этап
   119, В-5.6). Один упавший запрос тарифа уносил вместе с кнопками и
   собранные дорожки. Теперь упавшая матрица — не «ещё грузится»:
   список показываем, кнопки прячем, замок не рисуем вовсе, потому что
   подпись «доступно в Premium» при неизвестном режиме была бы
   выдумкой.

   После этих двух правило вынесено из разметки в `panelAccess()` и
   покрыто тестом: дважды ошибиться в одном клубке `if`-ов, который
   проверяется только глазами, — достаточный довод.

3. **А-2. Опросов было два, и они разошлись в худшем месте.** Экранный
   тик при сетевой осечке переставлял таймер, а тот, что запускался
   после сборки, — останавливался насовсем и показывал ошибку. То есть
   одна икота сети после УДАЧНОЙ платной сборки оставляла человека с
   вечным «собирается» и с красным сообщением о неудаче там, где деньги
   потрачены не зря. Теперь реализация одна на оба пути, и ошибку
   опроса человеку не показываем вовсе: видимой она бывает только у
   первой загрузки и у самой сборки.

4. **А-3. «Дорожек пока нет» показывалось и когда список не
   загрузился.** «Не смогли показать» и «показывать нечего» — разные
   ответы, и второй из них человек читает как «сборка не сохранилась».

5. **А-4. Рядом с готовой дорожкой предлагался отдельный файл
   голоса.** Голос — это речь без подложки; залитый вместо дорожки, он
   даёт ролик без фона, и заметить это можно только по уже
   опубликованному результату. Теперь голос предлагается только там,
   где полной дорожки нет, — как запасной выход, ради которого он и
   отдаётся.

6. **А-5. «Собрать недостающие» не показывала, что работа идёт.**
   Очередь из четырёх сборок занимает минуты, а кнопка была просто
   неактивной — то есть выглядела сломанной, а не занятой.

## 12. Чего в этом ТЗ сознательно нет

- **Автодубляжа YouTube.** Площадка умеет дублировать сама, и это
  бесплатно. Но качество машинное, а у продукта есть клонирование
  голоса — ради него всё и затевается. Автодубляж стоит держать как
  запасной путь для языков, которых нет у наших провайдеров.
- **Языков сверх пяти локалей продукта.** Resemble умеет восемь, но
  интерфейс, описания и субтитры живут на пяти — дорожка на языке, на
  котором нет описания, приносит зрителя на страницу, которую он не
  прочитает.
- **Перевода уже опубликованных роликов задним числом.** Сначала
  конвейер на новых, потом разовый прогон по архиву.
- **TikTok.** У него своя механика локализации, и смешивать её с
  YouTube в одном ТЗ значит не сделать ни того, ни другого.
