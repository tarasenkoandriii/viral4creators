## 2. Обучалка: два режима — свой сайт и чужой сайт со своим аккаунтом

### 2.1. Как определяется режим

Режим не выбирает пользователь. Его определяет **статус хоста** во
внутреннем API `sites-backend` (Ш1):

| Режим | Условие | Как попасть |
|---|---|---|
| **A — свой сайт** | хост подтверждён (DNS/файл/мета) кабинетом, к которому привязан этот пользователь генератора | шаг «Подтвердите сайт» в мастере `CLIENT_SITE` (Ш1) |
| **B — чужой сайт, свой аккаунт** | хост не подтверждён этим пользователем | по умолчанию; одно подтверждение прав на аккаунт (П-Т2) на хост |

- Ш1 перестаёт быть воротами и становится **повышением**. Подтвердил
  владение — черновик переходит в A со всеми послаблениями, без потери
  работы.
- Владелец сайта, не прошедший подтверждение, попадает в B. Ограничения B
  мягкие, поэтому подтвердить сайт выгодно, но не обязательно.
- Если хост подтвердил **другой** кабинет и включил там «запретить
  обучалку посторонним», режим B для этого хоста закрыт. Это часть
  П-Т11 (opt-out).

### 2.2. От кого защищаемся в режиме B

Технически проверить, что аккаунт на чужом сайте принадлежит именно этому
человеку, **нельзя**: у нас нет доступа к базе того сайта. Поэтому
«запрет чужих аккаунтов» достигается не проверкой, а тем, что
злоупотребление становится **дорогим, заметным и юридически
непривлекательным**. Сценарии:

| Сценарий | Кто | Что получает без защит | Чем закрывается в B |
|---|---|---|---|
| Перебор паролей (credential stuffing) через наш сервер | владелец утёкшей базы паролей | наш IP и браузер для проверки чужих логинов; IP Hetzner попадает в блок-листы | П-Т6 (не больше 3 разных логинов на хост), П-Т8 (попытки входа), П-Т9 (глобальный потолок), П-Т12 (журнал) |
| Вход в украденный аккаунт и съёмка его содержимого | тот, у кого чужие креды или куки | кадры чужого кабинета; живая сессия жертвы в нашей БД | П-Т2 (подтверждение прав — юридический щит и сдерживание), П-Т3 (пароль не хранится), П-Т12 (журнал: кто и когда), жалоба → заморозка (П-Т11) |
| Автоматизация против условий сайта: спам-формы, фейковые регистрации, отзывы | спамер | наш браузер как бесплатный бот | лимиты раундов (есть), П-Т7 (много несвязанных доменов → модерация), П-Т13 (подтверждение опасных кнопок), opt-out (П-Т11) |
| Чувствительные сервисы: банк, госпортал, почта, криптобиржа | любой из выше | максимальный ущерб жертве, ПДн третьих лиц в кадрах | П-Т10 (категории запрещены в B) |
| Внутренняя сеть хостинга (SSRF) | любой | метаданные облака, панели | Ш0.2–Ш0.3 (прокси) — от режима не зависит |

### 2.3. Модель защит

| Защита | Режим A — свой сайт | Режим B — чужой сайт, свой аккаунт |
|---|---|---|
| Фильтрующий прокси, egress (Ш0) | да | да |
| Подтверждение владения (Ш1) | **обязательно** — это и есть режим A | нет (нельзя — см. уточнение владельца) |
| Подтверждение прав на аккаунт и согласия с условиями сайта (П-Т2) | не нужно: владение доказано | **обязательно**, один раз на хост, текст с версией, запись в журнал |
| Хранение пароля | да: реестр тестовых учётных записей сайта (Ш2), аренда, срок, журнал | **нет**: пароль используется один раз для входа и не сохраняется (П-Т3) |
| Хранение сессии (кук) | ≤ 7 дней, только регистрируемый домен (Ш2) | ≤ 7 дней или «одноразово», только регистрируемый домен; в **личном** хранилище пользователя (П-Т4) |
| Кто видит учётку | участники кабинета по правам; QA по аренде (Ш2) | только сам пользователь; QA — никогда; в реестр сайта не попадает |
| Несколько тестовых пользователей (роли, пакеты) | да (Ш2) | не больше 3 разных логинов на хост за 30 дней (П-Т6) |
| Запрещённые категории (банки, госпорталы, почта, крипто, платёжки, медицина) | нет: подтвердивший домен банка — это банк | **запрет** (П-Т10); соцсети и маркетплейсы — через модерацию |
| Несвязанные домены на одного пользователя | без ограничения | не больше 3 за 30 дней, дальше — модерация (П-Т7) |
| Опасные кнопки (оплатить, удалить, отправить) | предупреждение (`danger-words.ts`, есть) | подтверждение на каждый такой клик (П-Т13) |
| Попытки входа | без повторов (QA §3.6) | не больше 2 неудачных в час на черновик (П-Т8) |
| Суточные лимиты | на пользователя (есть) + глобальный потолок (П-Т9) | то же; лимит B можно задать ниже отдельно |
| Opt-out сайта и жалобы | — | реестр opt-out, abuse-контакт, жалоба → заморозка ≤ 1 ч (П-Т11) |
| Журнал | AuditLog Ш2 | AuditLog: режим, подтверждение прав, живые сессии, HMAC логина — без содержимого (П-Т12) |
| Кадры | приватно или со сроком (Ш0.6, Ш3) | то же; срок хранения короче — по умолчанию 14 дней после решения |

### 2.4. Что меняется в плане Э-С

- **Ш1:** подтверждение владения — повышение до A, а не ворота для всех.
  Оценка Ш1 не растёт. Плюс +1 день на определение режима и переход
  черновика (П-Т1).
- **Ш2:** реестр `site_test_accounts` и `site_credentials` — **только для
  режима A**. Для B нужна отдельная сущность «сессия пользователя на чужом
  сайте» (`user_site_sessions`): привязка к пользователю генератора, а не
  к кабинету сайта; только куки, без пароля; без аренды для QA (П-Т4,
  +1 день к Ш2).
- **Ш0.1:** живой вход включать обратно после П-Р1 (правила хоста
  применены, `LIVE_LOGIN_EGRESS_DENY` задан). Режим B с живым входом —
  после П-Т2.
- **Юрист** (вопрос 10 аудита): к пунктам там добавить текст
  подтверждения прав для режима B (П-Т2) и правило «пароли третьих
  сайтов не храним».
