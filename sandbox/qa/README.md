# Первый этап управления QA

Это выполняемая основа пилота sandbox/TMA, а не готовая клиентская TMS.

`catalog.json` хранит стабильный ID, версию, шаги, требования, тип и обязательные окружения. ID прописан в заголовке Playwright `[SBX-LOGIN]`. При изменении смысла кейса или шагов повысить version; запуск копирует весь каталог, поэтому последующее изменение файла не меняет исторический отчёт.

Репортёр создаёт `test-results/qa-run.json`; существующий GitHub Actions upload-artifact сохраняет его вместе с QA-отчётом на 14 дней. Результат содержит версии кейсов, матрицу, все attempts, flaky после failed→passed, отдельные автоматические/ручные статусы и незавершённые проверки. Неизвестные ID учитываются явно. Итог Playwright и статус приёмки различаются: зелёный браузерный запуск не закрывает обязательный ручной кейс.

В pilot-plan физические iOS/Android обязательны; эмуляция Chromium mobile их не заменяет. `recordAttempt` требует всех passed шагов перед ручным passed и не разрешает ручной результат под видом автоматического. Пользовательский интерфейс ручной приёмки, БД, tenant authorization, редактор каталога, CSV/JUnit импорт и права на артефакты ещё не реализованы. Не публиковать этот локальный модуль как клиентский API.

Сохраняется SHA исходников теста; deployed SHA неизвестен, пока явно не передан QA_DEPLOYED_SHA. GitHub checkout SHA не считается доказательством версии сайта. Тексты исключений, audio, tokens и traces не копируются в новый JSON; действующая политика Playwright-артефактов остаётся отдельной.

Проверки: `npm run test:qa-model`, затем `npm test`. Локальные проверки с выключенными внешними API корректно показывают skipped/not-run и incomplete.
