Ціль — дія відвідувача, яку ви вважаєте результатом: заявка, покупка, запис. Помічник рахує, скільки цілей було після розмови з ним, і надсилає звіт у ваш Telegram.

:::claim goal-stats
## Що показує статистика

- **Прямі конверсії:** помічник довів — ціль після розмови з ним у межах вікна атрибуції.
- **З участю помічника:** відвідувач говорив з помічником, але не обов'язково завдяки йому.
- **Розвантаження операторів:** розмови, вирішені без людини, і ≈ години роботи оператора за вашою оцінкою хвилин на питання.
- Експорт у CSV з кабінету; ранкова зведенка в бот.

Приріст «завдяки помічнику» ми не показуємо: для нього потрібна контрольна група — це наступний етап продукту.

## Вебхук сервер-сервер

Подія зі свого сервера надійніша за подію зі сторінки: її не зупинить блокувальник, і вона несе справжню суму та повернення.

- **Адреса:** `POST %%webhookPath%%` на API помічника — точна адреса та секрет у кабінеті («Інтеграції»).
- **Тіло:** JSON `goalKey`, `orderId`, `status` (`completed`, `refunded`, `cancelled`), `occurredAt` (ISO 8601), необов'язкові `value` і `currency`.
- **Заголовок `%%signatureHeader%%`:** `%%signatureFormat%%`, де `t` — час у секундах Unix. Підписуються саме ті байти, що йдуть у тілі.
- **Вікно:** ±5 хвилин від часу сервера; старіший підпис відхиляється.
- **`Idempotency-Key`:** номер замовлення. Повтор з тим самим ключем не подвоює ціль; `refunded` чи `cancelled` для того самого замовлення — віднімає.


Table: Відповіді вебхука
| Код | Причина |
| 200 | Подію прийнято (або це повтор) |
| 401 | Немає підпису, він старий або чужий |
| 400 | Немає `Idempotency-Key`, тіло не за схемою, невідома ціль |
| 422 | Неправильний номер замовлення |
| 429 | Забагато подій (понад 120 за хвилину на сайт) |
