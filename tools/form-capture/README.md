# Локальный сборщик структуры формы, v0.2.3

Для Chrome/Edge (Manifest V3). Включите режим разработчика в разделе расширений и загрузите распакованную папку. Установка выполняется пользователем; расширение не устанавливается из кабинета автоматически.

Откройте нужную HTTPS-страницу в своей сессии, нажмите расширение, выберите номер формы с нуля, соберите и проверьте снимок, сохраните JSON. В QA → «Стенды» импортируйте его как ожидаемую или текущую структуру. Перед сравнением укажите одинаковый безопасный URL формы: экспорт содержит только origin, без пути/параметров/фрагмента. Путь может содержать персональные идентификаторы, поэтому автоматически не экспортируется.

Разрешения: activeTab и scripting, только после действия пользователя. Нет host permissions, фонового наблюдения, сети, доступа к cookies, localStorage или токенам. В режиме снимка не читает input.value, textarea.value или selectedIndex; имена/id экспортируются только в виде непрозрачных локальных ключей. Это не криптографическое обезличивание и не гарантия анонимности. Структуру и URL перед передачей нужно проверить.

Ограничения: обычные form/input/select/textarea основного документа. Варианты select и подписи не экспортируются (они могут содержать личные данные), скрытые поля пропускаются; нет iframe/Shadow DOM, условных шагов и пользовательских компонентов. Radio и другие неподдержанные типы, поля без стабильного id/name и дубликаты блокируют снимок. Одинаковые снимки не доказывают полного совпадения форм и не разрешают заполнение.

Никаких отправок формы, принятия условий и переноса credentials. Заполнение выбранных простых HTML-полей доступно только отдельным действием, описанным ниже. Автоматическая отправка снимка в кабинет отсутствует.

Основа разрешений и внедрения функции: [Chrome scripting API](https://developer.chrome.com/docs/extensions/reference/api/scripting). Полный install/popup/download цикл в установленном Chrome/Edge требует отдельной приёмки; проверка функции через DOM сама по себе его не подтверждает.


## Автоматическая приёмка установленного расширения

`cd tools/form-capture/tests && npm ci && npx playwright install chromium && npm test`.

Семь E2E загружают расширение в отдельный временный профиль Chromium: реальный chrome.scripting API, UI сборщика, предпросмотр и скачивание JSON; отказ без доступа; очистка прежнего экспорта и понятная ошибка после неудачного повторного сбора. Только синтетические данные и локально перехваченный HTTPS fixture, пользовательский профиль не используется.

Тестовая копия manifest получает разрешение **только** на capture-fixture.invalid и делает popup доступным во fixture iframe; это необходимо для headless UI harness. Поставляемый manifest не изменяется, не содержит host_permissions/web_accessible_resources, что проверяет unit-тест и контроль архива. Этот E2E не подтверждает жест активации activeTab через настоящую кнопку панели Chrome/Edge: ручная приёмка установки и toolbar popup остаётся открытой. Стендовый iframe не является способом использования production-расширения.

Документация подхода: [Playwright Chrome extensions](https://playwright.dev/docs/chrome-extensions).


## Перенос подготовленных данных (0.2.0)

1. В кабинете QA → «Стенды» откройте запись генеративного мока → «Подготовить перенос полей».
2. Импортируйте снимок целевой формы, укажите полный безопасный URL и номер формы, сопоставьте выбранные поля. Экспортируйте проверенные данные в qa-form-transfer.json. Это локальный файл с выбранными бизнес-значениями — не публикуйте его без проверки.
3. В расширении на целевой странице импортируйте план. «Сверить и показать изменения» ничего не записывает: показывает фактические подписи, прежние и новые значения, адрес и версию источника.
4. После проверки нажмите «Заполнить выбранные поля без отправки». Вкладка, адрес, структура и значения повторно проверяются. При изменении — отказ, нужен новый предпросмотр. После заполнения кнопка отключается; повтор без новой сверки невозможен.

Поддержаны только видимые доступные native HTML text/email/url/number и textarea. Не вызываются input/change, focus, click, submit и requestSubmit. Управляемые React/Vue формы могут сбрасывать вставленное значение или не включать его в отправку — для них нужен отдельный адаптер. Страница может самостоятельно читать вставленные данные; расширение не гарантирует отсутствие собственной обработки сайта.

Generated MOCK-поля, состояния workflow и поля со служебными именами исключены при экспорте. Расширение независимо блокирует пароли, OTP/платёжные поля, checkbox/select/file/date, disabled/readonly/скрытые поля и pattern. Известные MOCK/placeholder/служебные URL и типичные token-паттерны отвергаются. Это не универсальный DLP: оператор проверяет выбранные значения и назначение полей. Нельзя переносить секреты под видом обычного текста.

Снимок структуры не содержит значений. Локальный предпросмотр переноса **читает текущие значения только выбранных бизнес-полей** и подписи, хранит их в памяти popup до закрытия/новой сверки; в backend они не отправляются. План — статический снимок записи; актуальность серверной версии после экспорта не проверяется, версия показывается пользователю.

При дрейфе перенос блокируется и новый структурный снимок доступен через «Скачать JSON». Импортируйте baseline/current в сверку кабинета: существующий API создаст QA finding. Автоматического обращения расширения в API, создания задачи без импорта, доверенной подписи baseline и интеграции с репозиторием пока нет. Самостоятельно подготовленный/изменённый план не считается доверенным адаптером.


### 2026-10-15 · Передача изменений формы 0.2.1

При блокировке переноса из-за изменения структуры расширение предлагает «Открыть QA со снимками изменений». Нужен новый план переноса с siteId; старые планы продолжают работать, но требуют ручного импорта снимков. Передаются только идентификатор стенда, типы полей и ограничения через fragment URL на фиксированный адрес кабинета. Значения полей и записи мока не передаются. Адрес сворачивается до origin: при нескольких формах оператор уточняет одинаковый безопасный путь в обоих снимках перед сверкой.

Кабинет проверяет формат и доступность стенда в текущем аккаунте/сайте, показывает снимки и требует отдельное действие для создания замечания. Открытие ссылки само по себе ничего не записывает. Fragment не отправляется HTTP-серверу, но сохраняется в истории браузера; не добавляйте конфиденциальные данные даже в имена полей. Фоновая доставка, подписанная идентичность формы и автоматическое исправление мока остаются в TODO.


### 0.2.2 · Подсказки загрузки
После импорта имя JSON и число выбранных полей показываются отдельно от очищаемого поля выбора файла. ZIP расширения и JSON снимка не являются планом переноса; интерфейс объясняет различие. Для chrome:// ошибки сборщика/переноса предлагают открыть HTTPS-сайт и снова нажать Q. Разрешения не изменились. Уже установленная 0.2.1 сохраняет работоспособность; для новых подсказок обновите локальную папку расширения до 0.2.2 и нажмите «Обновить» на его карточке.


### 0.2.3 · Панель структуры внутри HTTPS-страницы
Настоящий клик Q открывает popup и внедряет отдельную панель в текущую страницу через activeTab. После закрытия popup панель остаётся доступной браузерным инструментам, включая Intel Mac без управления окном. Один пользовательский клик Q нужен для выдачи разрешения; панель не обходит этот шаг. Разрешения остаются activeTab/scripting, без постоянного доступа к сайтам.

В панели доступны сбор структуры, загрузка JSON плана, сравнение и переход в QA. Значения полей страницы не читаются, entries из плана отбрасываются; заполнения и отправки формы здесь нет. Передаются только origin, непрозрачные ID полей и ограничения. Совпадение структур не создаёт перехода; повторное открытие Q не добавляет вторую панель. Содержимое панели доступно самой странице — не загружайте секреты. Создание замечания остаётся отдельным действием в кабинете с серверной проверкой доступа и дедупликацией.

Сборка `python3 scripts/build-form-workbench.py`; проверка `--check`. 4 unit и 10 Chromium E2E проверяют функцию/установленную тестовую копию. Тестовый host grant не является доказательством production activeTab.

### 0.2.4 · Быстрый аудит страницы и локальный отчёт
После обычного клика Q в панели доступна кнопка «Проверить открытую страницу». Проверяются шесть эвристик: наличие title, lang, viewport, подписи видимых полей, alt видимых изображений, повторяющиеся ID. Отчёт Markdown содержит origin, время, числа сигналов и рекомендации, без значений полей, URL-пути и образцов содержимого. Никаких сетевых вызовов, AI, заполнения, отправки форм или автоматического создания замечаний. Повтор проверки не создаёт сущностей в кабинете.

Это входной бесплатный инструмент для самостоятельного знакомства с QA. В рекламе допустимо «Быстрая проверка открытой страницы: 6 проверок и отчёт». Не обещать полный аудит сайта, сертификацию доступности, безопасность, проверку бизнес-логики или скорость. Shadow DOM, iframe, контраст, клавиатура, другие страницы и состояния не проверяются. «Сигнал не найден» не означает, что ошибок нет. После отчёта — отдельная полноценная проверка сценария на sandbox/тестовом аккаунте.


Живая read-only проверка новой панели на собственном публичном sandbox: из `tools/form-capture/tests` запустите `node live-quick-audit.mjs /absolute/path/result.json`. Потребуется установленный Chromium тестового пакета. Создаётся временная тестовая копия расширения с host grant **только sandbox**, после проверки профиль удаляется. Проверяет отчёт/скачивание/повтор, неизменность полей и нулевые отправки; не создаёт findings и не вызывает платные API. Не является доказательством настоящего toolbar activeTab рабочего Chrome.
