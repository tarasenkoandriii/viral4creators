# Темп обучалок в постпродакшене

Требование владельца, 06.10.2026. План реализации, функция ещё не добавлена.
Выбранное поведение: естественная скорость речи, изменение пауз между
кадрами. Нельзя ускорять голос, обрезать реплики или переносить их на
чужие кадры ради заданной скорости.

## Найденные ограничения текущей реализации

- PostprodVideosService/PostprodVideoScreen используют sessionId и
  обычные сгенерированные ролики. TutorialVideoAsset — другой объект;
  его нужно подключить к постпродакшену отдельным типом, с проверкой
  владения через clientSiteDraftId, а не выдавать чужие админские демо.
- Сценарный сборщик уже поддерживает audioUrl на каждом SlideshowFrame
  и единую временную сетку frameSpansSeconds. Есть альтернативная
  озвучка одной дорожкой на весь ролик — без привязки реплик этот
  вариант нельзя безопасно редактировать по паузам.
- Транзитные PNG/ASS после сборки удаляются; в TutorialVideoAsset нет
  сохранённого монтажного плана. Для повторной сборки необходимы
  отдельные исходники с явной политикой хранения.
- Клиентские обучалки сейчас собираются через uniformFrames без
  покадровой озвучки. Не обещать пользователю синхронизацию речи там,
  где ещё нет дорожки; немой сценарий темпа поддержать отдельно.

## Поведение интерфейса

В постпродакшене обучалки — блок «Темп»: спокойнее / обычный / быстрее,
затем точная настройка при необходимости. Подпись: «Меняет паузы;
скорость речи сохраняется». Показывать рассчитанную итоговую длительность
и предупреждение о достигнутом минимуме пауз. Не обозначать настройку
как гарантированное 2× ускорение всего ролика.

Предпросмотр и экспорт используют один монтажный план. Изменение лишь
HTMLVideoElement.playbackRate не выполняет требование: оно ускоряет речь
и не меняет файл. Сначала предпросмотр новой сборки, затем сохранение
отдельной версии. Исходник остаётся доступен; ошибка сборки не заменяет
действующий ролик. Повторная отправка во время сборки не запускает дубль.

## Монтажный план

Сохранить versioned timeline manifest: sourceAssetId, owner, sourceHash,
locale, тема/режим, fps, motion, ordered frames с устойчивым stepIndex,
image/sourceSegment, исходной длительностью, speech audio reference и
измеренной длительностью, текстом/таймингами подписи, минимальным временем
чтения и указателем. Отдельно сохранять происхождение каждой дорожки.
Один frameId используется картинкой, репликой и подписью.

Исходники для редактирования не класть под удаляемый транзитный префикс.
Они живут не дольше принадлежащей пользователю обучалки и удаляются
вместе с ней; повторные версии не размножают общие исходники. Согласовать
лимит хранения, не отключать текущую уборку всех транзитных файлов.

Для старых MP4 без manifest блок темпа недоступен с объяснением и
предложением пересобрать из доступного черновика. Не угадывать границы
реплик по общей длине файла. Общую звуковую дорожку разрешать лишь после
достоверной сегментации по кадрам; иначе сохранять исходник без изменения.

## Пересчёт времени

Для каждого кадра исходный span делится на речь и свободную паузу.
Темп масштабирует только паузу. Речь остаётся той же длительности;
нижняя граница кадра — max(вся речь + защитный запас, время чтения).
Если уже исходный кадр короче реплики, сначала исправить этот дефект,
а не превращать отрицательную паузу в успешное ускорение.

Защитный запас и минимальная пауза — константы общей рубрики. Переходы
учитывать в целых кадрах OUTPUT_FPS: начало следующего кадра не может
наступить до конца реплики предыдущего. Уменьшать overlap либо
ограничивать сокращение паузы; никогда не резать речь и не допускать
наложение двух реплик. Округление кадров и аудиосэмплов должно сохранить
этот инвариант, а не сокращать сегмент ниже измеренной длины аудио.

Из новой сетки одновременно вычислить video spans, audio delays,
длительности тишины, ASS-caption timings, анимацию указателя и общую
длительность. Ни setpts для всего MP4, ни atempo для голоса не применять.
Для намеренно немого кадра использовать минимальное время чтения;
не исключать его из последовательности. Нет обязательной реплики из-за
сбоя синтеза — дефект исходника, а не разрешение сократить кадр до нуля.

Ключ идемпотентности пересборки: sourceHash + manifestVersion +
нормализованный темп + настройки переходов. Все изменения считаются
от исходного manifest, не от предыдущей ускоренной версии, чтобы
возврат «обычный» не накапливал округления. Для публичного демо новая
версия требует повторной проверки качества и операторского одобрения.

## API и порядок реализации

1. Сохранение manifest/редактируемых исходников и миграция модели;
   старые записи явно non-editable. Сначала общий чистый планировщик
   темпа, затем интеграция с имеющимся planSlideshow.
2. Защищённая коллекция обучалок пользователя в постпродакшене,
   дискриминированный тип session/tutorial вместо подмены sessionId.
   Endpoint пересборки по assetId проверяет владельца, complete-статус,
   входной темп, доступность исходников и незавершённую задачу.
3. Асинхронный submit/poll через существующий ffmpeg-api, отдельная
   версия результата, учёт реальной стоимости пересборки. Не вызывать
   синтез речи повторно, если пользователь меняет только темп.
4. UI с итоговой длительностью, предпросмотром/сохранением, возвратом к
   обычному темпу и объяснением ограничения ускорения речью.
5. Проверка качества Gemini по новому manifest, включая привязку
   реплики к кадру; техническая проверка таймингов остаётся обязательной.

## Приёмка

- Длинная реплика и короткая пауза: ускорение не обрывает речь;
  следующий кадр начинается после завершения её реплики.
- Чередование озвученных и немых кадров, пропуски stepIndex, переходы,
  длинные подписи: все три дорожки используют одни границы.
- Замедление увеличивает паузы, голос остаётся естественным; возврат к
  обычному темпу восстанавливает исходную сетку.
- Экспорт совпадает с предпросмотром; нет дрейфа на длинной обучалке.
  Проверять фактическое декодированное видео/аудио, а не только команду.
- Двойной клик/повтор cron не создают платную дублирующую сборку;
  чужой asset недоступен; failed-версия не затирает исходник.
- Без manifest/с корректно не разделённой общей озвучкой функция
  объясняет ограничение и не создаёт рассинхронизированный ролик.
