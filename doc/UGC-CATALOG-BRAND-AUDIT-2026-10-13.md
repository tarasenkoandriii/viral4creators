## Найдено и исправлено

### 1. Частичные отказы товарного крона давали SUCCESS

Рабочие задачи возвращают счётчики и продолжают обработку остальных строк.
Обёртки планового и ручного запуска раньше распознавали такие ошибки только
у Tutorial. Добавлен общий cronResultFailed с явным контрактом пяти товарных
задач: failed/renderFailed/grokBatchItemsFailed, failedItems/failedRuns,
gaveUp и ошибки опроса рендера. Частичный отказ теперь записывается FAILED
при сохранении исходного результата и подробной числовой сводки.

Повтор webhook, бюджетная отсрочка, пропущенная товарная строка и пустая
очередь сами по себе не становятся отказом. Контракты других кронов сохранены.

### 2. Отказ скачивания или разбора фида исчезал из счётчиков

Фаза скачивания записывала FAILED на самом импорте, но возвращала только
число обработанных запусков. Добавлен failedRuns; failedItems остаётся
отдельным показателем отказов создания товаров. Сетевая ошибка сохраняет
существующий backoff, а SSRF/пустой/слишком большой фид сохраняют терминальный
отказ. Теперь оператор видит провал в summary без включения debug.

### 3. Ошибка проверки рендера линейки/A/B терялась из результата тика

Добавлен renderPollErrors. Исключение при getVideoStatus больше не даёт
зелёный тик. Замок снимается, другие строки продолжают выполняться,
сам рендер остаётся GENERATING для следующего опроса. Это отделено от
renderFailed: временный сбой проверки не должен повторно заказать платный рендер.
Счётчик относится к исключениям; штатный pending у провайдера не считается ошибкой.

## Ограничения и оставшаяся приёмка

- TMA во встроенном браузере сейчас не авторизован: postprod корректно
  показывает требование входа. Авторизованная визуальная приёмка товаров,
  редактора брендбука и партии в этой сессии не выполнена.
- Последний подтверждённый внешний блокер — FFmpeg API paymentRequired 402
  из [аудита Tutorial/Greeting](TUTORIAL-GREETING-AUDIT-2026-10-13.md).
  Наличие доступного старого ролика не подтверждает восстановление submit.
- Нужна контролируемая настоящая партия минимум из двух товаров с брендбуком,
  затем A/B и фид, чтобы подтвердить непустые плановые тики. Без такой партии
  нельзя назвать линейки production-принятыми только на основании зелёного CI.
- DONE у партии означает завершение генерации. Для качества отдельно проверять
  postStatus/voiceStatus: skipped может быть допустимым выбором пользователя,
  а отказ постобработки нельзя трактовать как готовую озвучку. Успешный исходный
  рендер сохраняется, автоматический повтор платной генерации не добавлен.
