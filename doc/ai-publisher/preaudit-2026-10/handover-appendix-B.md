Оценить и провести независимый аудит документации и тестирование AI Publisher в составе viral4creators.

- **Основа:** требования Publisher 2.2.
- **Первый обязательный объём:**

- Остальные production-модули получают явно согласованный охват и смету (раздел 3).
- **Результат:** воспроизводимые протоколы, реестр дефектов, матрица покрытия и подписанное заключение по конкретной версии и каждому шлюзу.

## 4. Готовность стенда и доступов (план §11)

### Что у нас есть

- **Сквозной стенд E2E:** `scripts/publisher-e2e.sh [--site]` (Р-PUB-Z2-20/28).
  - Свежая база из всех миграций и сид: кабинет, шесть ролей продукта, подтверждённый хост, протокол приёмки стенда.
  - Сборка `dist` из текущих исходников по метке.
  - Драйвер — клиент кабинета assist под участниками с ролями. initData подписан тестовым ботом стенда.
  - С `--site`: сборка `publisher-site` в своей копии, https-домен через локальный CONNECT-прокси, Chromium.
  - Итог — JSON по шагам с доказательствами. Финальный прогон — 51/51.
- **Часы стенда:** `PUBLISHER_STAND_CLOCK` (Р-PUB-Z2-21). Только при `NODE_ENV=development|test` и вне Vercel; маршрут `/__stand/publisher/clock` закрыт `CRON_SECRET`. Используются для D42/D72/D90 на синтетическом календаре.
- **Локальное хранилище копий:** `PUBLISHER_STAND_BACKUP_DIR` (Р-PUB-Z2-22). Нужно для бэкапа и восстановления без Vercel Blob.
- **Тестовые роли:** владелец кабинета, `product_owner`, `editor`, `operator`, `analyst`, `sales`, `viewer`, `admin` (`publisher=admin`), участник без грантов, участник с `publisher=none`, аноним, второй кабинет для изоляции (TD-01/TD-02). Матрица операций — design §4.2; динамическая сверка — `D1-role-matrix.csv`.
- **Тестовые данные TD-01…TD-11:** фикстуры jest (в т. ч. TD-08, TD-09, TD-10) и синтетика S1–S7 только в `kind=eval`.
- **CI:** джоба `publisher-stand` (E2E против настоящего backend) добавлена. В GitHub Actions ещё не запускалась.
