## 0. Инфраструктура (без ключей внешних AI)

- [ ] `cd backend && npx prisma generate` — клиент генерируется; после
      этого `npx tsc --noEmit` в backend/ чистый (сейчас ~30 ожидаемых
      ошибок вида «Property 'x' does not exist on type 'PrismaService'» —
      все из-за отсутствующего клиента, см. `doc/TELEGRAM-ADMIN.md` §5).
- [ ] `npx prisma migrate deploy` на реальной (или dev-) базе — накатились
      все миграции (сколько их — в шапке выше; число здесь дублировалось и
      успело разъехаться), таблица `_prisma_migrations` заполнена. Если
      база уже содержит первые миграции — deploy докатит остальные.
- [ ] `make up` (docker-compose.dev.yml) — стартуют db, backend, frontend
      (:5173), admin (:3002), landing (:3003). `GET :3000/api/health` →
      `{"status":"ok","database":"up"}` (эндпоинт появился на этапе 28 —
      до него был обещан документами, но не существовал).
- [ ] Админка → «Настройки»: каждая переменная из `.env.docker` видна и
      с ожидаемым цветом — в т.ч. `SERPAPI_API_KEY`, `YOUTUBE_API_KEY`,
      `YOUTUBE_SEARCH_DAILY_LIMIT_PER_USER`, `AUDIT_AUTO_ITERATIONS_LIMIT`,
      `PROJECT_LINE_ITEM_LIMIT`, `FFMPEG_API_KEY`, `VOICE_API_KEY`.
      **«Всё зелёное» на dev-стенде недостижимо by design** (Б-5.3):
      `ALLOW_DEV_AUTH=true` и незаданные ключи дают жёлтые строки, и это
      правильный ответ, а не расхождение. Проверяется другое: жёлтых
      ровно столько, сколько ключей вы не задали, и ни одна строка не
      зелёная при пустом ключе.

## 6b. Уборка хранилища (этап 26, §22)

Полностью — в `doc/STORAGE-AUDIT.md`; здесь минимум, который стоит
прогнать один раз.

- [ ] Довести сессию до готового ролика (кадры-превью, своя сцена,

      `curl -H "Authorization: Bearer $CRON_SECRET" .../api/cron/cleanup-sessions`
      → в ответе `deletedBlobs` совпадает с числом файлов, префикс
      `sessions/<id>/` в панели Blob пуст, `hasMoreSessions=false`.
- [ ] Разбор той же сессии попал в библиотеку → карточка в «Библиотеке»
      после уборки по-прежнему с обложкой (копия лежит в `library/…`).
- [ ] Удалить товар с фото → файл исчез из `projects/…`; удалить проект с
      несколькими товарами → исчезли все их фото; удалить манифест бренда
      → пуст префикс `brand-manifests/<id>/` (этап 27).
- [ ] Удалить запись в админской «Библиотеке» → её копии кадров под
      `library/<ключ>/` исчезли.
- [ ] Метла (этап 27): `GET /api/cron/sweep-orphans?dryRun=1&limit=1000`
      с `CRON_SECRET` → в отчёте `deleted` показывает, что было бы
      удалено, `skippedTooNew` не даёт задеть свежие файлы. Убедиться, что
      в списке нет ничего живого, и только потом запустить без `dryRun`;
      при непустом `cursor` повторить с ним.
- [ ] Метла в расписании (этап 29): в логах Vercel после ночного прогона
      есть строка с разбивкой по видам файлов (`generated`, `previews`,
      …), числом осиротевших сессий и возрастом старшего файла. Убрать
      `BLOB_READ_WRITE_TOKEN` и дёрнуть маршрут руками → в логе прямо
