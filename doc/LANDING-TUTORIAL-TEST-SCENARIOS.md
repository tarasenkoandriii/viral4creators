# Тестовые сценарии: лендинг + «обучалка» + ИИ-консультант

Ручной чеклист для стенда с реальным деплоем (сеть до Gemini/Grok/Veo,
Postgres, `FIXTURE_*`) — песочница разработки не может исполнить ни один
из этих сценариев целиком (нет сети до внешних API и БД, см.
`doc/CI.md` и «Ручной запуск крона обучалок» в конце документа). Список
родился из аудита от 2026-09-16 (`doc/PRODUCT-PROJECT-IMPLEMENTATION-PLAN.md`,
этап 104) — часть сценариев (блок 5) прямо целится в найденные и
исправленные там неточности, чтобы они не вернулись при следующей
правке контента.

Область: главная страница лендинга, `/[locale]/how-it-works`
(«обучалка»), плавающий и встроенный виджет ИИ-консультанта, их связка
с реальным мастером генерации в мини-аппе. Пять локалей: `ru`, `uk`,
`en`, `de`, `es`.

## 1. Главная страница лендинга

1.1. Открыть `/ru` — все секции рендерятся по порядку (hero → demo →
features → how → plans → details → roadmap → faq → final-cta →
footer), без пустых блоков и разорванной вёрстки.

1.2. Повторить 1.1 для `/uk`, `/en`, `/de`, `/es` — тексты переведены
полностью (нет забытых русских фраз), длинные строки не ломают карточки
(особенно немецкий — самые длинные слова).

1.3. Кнопка `hero.ctaPrimary` и `finalCta.cta` ведут на `TMA_URL` —
мини-апп открывается.

1.4. `hero.ctaDemo` прокручивает к `#demo`, видео YouTube грузится
(`DEMO_YOUTUBE_EMBED_URL`), ссылка «Смотреть на YouTube» открывает
`DEMO_YOUTUBE_URL` в новой вкладке.

1.5. Секция `#plans` — три карточки (Lite/Standard/Premium), у Premium
класс `plan-highlight`. Цена везде — `dict.plans.priceFree` («бесплатно»
на этой стадии, см. блок 5.4 про риск на будущее).

1.6. Футер: ссылки на оферту/условия использования открываются и
рендерят полный текст (`legal-content.ts`); на локалях кроме `ru`
дополнительно показывается `footer.legalNoticeOtherLocale`.

1.7. `<title>`/`meta.description`/`og:*` для каждой локали — открыть
через «Просмотр кода страницы», убедиться что `meta.description` не
пустой и соответствует словарю (см. 5.1).

## 2. Секция «Как это работает» (тизер, `#how`) и полная страница `/how-it-works`

2.1. На главной в `#how` — блок-схема из 10 боксов со стрелками между
ними, под ней — карточки первых шагов в укороченном виде
(`variant="teaser"`): у карточек нет разворачиваемых `details`, есть
`step-highlight` вместо них.

2.2. Клик по боксу диаграммы `#step-N` на главной ведёт на
`/{locale}/how-it-works#step-N` (не на тот же экран — `hrefBase`
разный у тизера и полной страницы).

2.3. Открыть `/ru/how-it-works` напрямую — все 10 карточек, у каждой
свой номер, иконка, бейдж плана там, где он должен быть (шаг 2 —
`premium`, шаги 4/5/7/9/10 — `standard`).

2.4. На полной странице (`variant="full"`) у каждой карточки открыт
список `details` сразу, КРОМЕ шага 10 («Постпродакшн») — там `<details>`
со сворачиваемым списком (5 пунктов результата).

2.5. У каждой карточки — кнопка «Спросить об этом шаге»
(`data-assistant-ask-step`, `data-assistant-step-title`). Клик, когда
консультант включён (`assistant_enabled=true` в админке), открывает
панель консультанта с предзаполненным вопросом
(`askAboutPrefill`, подставлен `title` шага) и контекстом `stepId`.

2.6. Клик по той же кнопке, когда консультант ВЫКЛЮЧЕН — кнопка не
исчезает (виден весь текст обучалки без виджета), но клик ничего не
делает (см. документированный аудит этапа 83: раньше кнопка была видна,
но мертва — это осознанно оставленное поведение, не регресс).

2.7. `body:not(:has(.assistant-widget))` — когда виджета в DOM нет
вовсе, у `.step-ask-btn` не должно быть активного hover-состояния
кнопки консультанта (CSS-фикс этапа 83, см. `globals.css`).

## 3. ИИ-консультант — плавающий виджет (главная)

3.1. `assistant_enabled=false` в админке (дефолт) — на странице нет ни
кнопки, ни панели, `document.querySelector('.assistant-widget')` —
`null`.

3.2. Включить `assistant_enabled=true` — на главной внизу справа
появляется плавающая кнопка `floatingLabel`; открытие/закрытие панели
работает мышью и Escape, фокус-ловушка не выпускает Tab за пределы
панели.

3.3. Пустая панель — 3 кнопки-подсказки из `emptyHint`
(`ASSISTANT_SUGGESTED_QUESTIONS`), клик по любой сразу отправляет её
текстом вопроса.

3.4. Отправить свободный вопрос («Сколько стоит 20-секундный ролик?»)
— ответ приходит потоково (SSE), видно `typing`-индикатор до первого
токена, курсор не мигает после `event: done`.

3.5. Заблокировать `text/event-stream` в DevTools (или проверить на
клиенте с урезанным Accept) — ответ всё равно приходит целиком через
JSON-запасной путь (`chatJson`), UI не отличается по результату, только
без пословного появления текста.

3.6. Задать больше 10 вопросов за 60 секунд с одного IP —
`errorRateLimited` после превышения окна `assistant-chat` (10/60с),
затем больше 60 за час — второе окно (`assistant-chat-hour`, 60/3600с).

3.7. Исчерпать дневной бюджет (`assistant_daily_budget_micro_usd`,
дефолт $3) — `errorBudget`, а не общая ошибка сети.

3.8. Оборвать соединение (закрыть вкладку/остановить запрос) на
середине ответа — в админке `/assistant` строка обмена не должна висеть
«в процессе» вечно; повторный тот же вопрос не должен тратить бюджет на
уже брошенный стрим (регресс-проверка HIGH-находки этапа 82/83:
`close`-событие обязано отменять поток у Gemini).

3.9. Действия в ответе (`<<<actions>>>`) — по одному сценарию на
каждый вид: `step` (кнопка «Показать шаг» переходит на нужный `#step-N`
на `/how-it-works`), `open-app` (ведёт в мини-апп), `plan` (прокручивает
к `#plans`, подсвечивает карточку через `assistant-plan-flash`), `faq`
(раскрывает нужный пункт FAQ), `legal` (открывает документ оферты/
условий), `video` (кнопка «Смотреть видео» — см. блок 6).

3.10. Модель предлагает больше одного видео-действия в ответе — сервер
должен оставить максимум одно (структурное ограничение `actions.ts`);
если такое пришло — это находка для нового аудита, не ожидаемое
поведение.

3.11. Проактивные триггеры (`assistant_proactive_enabled=true`,
дефолт вкл.) — по одному сценарию на каждый из пяти: долгая пауза на
шаге мастера (не на лендинге — см. блок 4 про интеграцию с ТМА),
скролл до секции `#plans`, попытка уйти с вкладки (exit-intent),
таймер бездействия на самой странице `/how-it-works`, повторный визит.
Каждый — только ОДИН раз за сессию (`sessionStorage`-антиспам), и НЕ
делает вызов модели сам по себе — деньги тратятся только если посетитель
кликнул по подсказке.

3.12. `prefers-reduced-motion: reduce` в ОС/браузере — точка-индикатор
на плавающей кнопке (`assistant-floating-dot`) не анимируется
(`assistant-pulse`).

## 4. ИИ-консультант — встроенный виджет (`/how-it-works`)

4.1. На `/ru/how-it-works` виджет встроен в раскладку страницы (не
плавает), присутствует секция `.assistant-widget-embedded` рядом с
карточками шагов.

4.2. При `assistant_enabled=false` секция реально пустая
(`:empty`-селектор из аудита этапа 83) — сетка страницы не оставляет
пустую колонку под несуществующий виджет.

4.3. Клик «Спросить об этом шаге» у карточки 2, 5 и 10 — каждый раз
открывает встроенную панель с правильным `stepId` (проверить по
запросу в devtools: `POST /assistant/chat` содержит `stepId: 2/5/10`
и `page: 'how-it-works'`).

## 5. Регресс найденных этим аудитом неточностей (2026-09-16)

Эти сценарии специально проверяют вещи, которые аудит нашёл
расходящимися с реальной бизнес-логикой и поправил — чтобы контент не
съехал обратно при следующей правке словарей.

5.1. На всех 5 локалях секция «Возможности» (`#features`, пункт про
рендер), FAQ («Сколько времени занимает генерация видео?») и блок
«Подробнее о проекте» («Что модель видит картинкой, а что — словами»)
упоминают ОБА движка — Grok и Google Veo 3.1, — а не только Veo. Grok
— указан как движок по умолчанию (он дешевле), Veo — как переключаемая
альтернатива с двумя качествами рендера.

5.2. Шаги обучалки 7, 8 и 10 (`/how-it-works`) не называют Veo
единственным рендерером: заголовок шага 7 — «Выберите формат и
референс-картинки» (не «...для Veo»), текст шага 8 упоминает «Grok или
Google Veo 3.1», шаг 10 («без нового рендера») не привязан к
конкретному провайдеру.

5.3. Карточки тарифов Lite/Standard — строки про форматы кадра и
референс-картинки не называют Veo единственным исполнителем
(«доступные без ограничений на любом режиме» / «для модели генерации»).

5.4. Секция `#plans` — если оператор когда-нибудь включит
`PLANS_BILLING_ENABLED=true` на бэкенде, проверить: лендинг **до сих
пор** покажет «бесплатно» (это открытый, задокументированный риск —
код-комментарий над секцией `plans` в `page.tsx`), — то есть перед
реальным включением оплаты эта секция ОБЯЗАНА получить отдельную
правку (текст + компонент), иначе пользователи увидят ложное
«бесплатно» при реальном списании денег. Считать сценарий проваленным,
если оплату включат, а эта строка чеклиста не была отдельно закрыта.

5.5. «Дорожная карта» (`#roadmap`) — ни один из шести пунктов, уже
отправленных в архив этим аудитом (выгрузка в YouTube/TikTok, страница
готового ролика, вшитые субтитры, еженедельная подборка в Telegram,
блог/RSS/карта сайта новостей, мультиязычный интерфейс, пакетная
генерация, A/B-варианты, импорт каталога, персонажи бренда + клон
голоса, ролики длиннее 8 секунд), не должен появиться в списке
«горизонтов» снова — эти функции уже в проде. Если планируется новая
функция с похожим названием — добавлять заново осознанно, не путать со
старой записью.

5.6. FAQ «Какие форматы видео поддерживаются?» — реально принимаются
`video/mp4`, `video/quicktime`, `video/x-msvideo` (MP4/MOV/AVI) до
100 МБ (`UploadVideoRequestDto`) — сверить при следующей правке лимита
загрузки, что FAQ на всех 5 локалях обновлён вместе с кодом.

## 6. Видео-действие консультанта (`kind: "video"`, этап 99/101)

6.1. В админке `/assistant` → «Видео-контент» одобрить (`reviewed:
true`) хотя бы одно видео с `subjectKey`, совпадающим с одним из 10
шагов обучалки.

6.2. Спросить консультанта про этот шаг («Как собрать состав кадра?»
для шага 5, если видео одобрено под `subjectKey: "5"») — ответ должен
предложить действие `video` с кнопкой `actionVideo` («Смотреть видео»),
ссылка ведёт на реальный `blobUrl` одобренной записи.

6.3. Снять одобрение (`reviewed: false`) с этого видео — тот же вопрос
больше не должен предлагать `video`-действие (сервис резолвит только
`reviewed: true`, `AssistantService.resolveVideoActions`).

6.4. Спросить про шаг, для которого одобренного видео нет вовсе —
ответ не содержит `video`-действия, ссылки на несуществующий/сырой
контент не появляется.

## 7. Ручной запуск крона обучалок (`tutorial-scenario-generate` / `tutorial-scenario-run`)

Этот блок — не то, что можно щёлкнуть мышью на лендинге, а прогон двух
крон-задач бэкенда, которые НАПРЯМУЮ производят контент для блока 6
(автозапись сценариев обучалки → регресс-прогон headless-браузером →
слайд-шоу → одобрение в админке). Инструкция, что нужно для реального
ручного запуска на стенде — песочница разработки не может исполнить ни
шаг (см. итог аудита этого этапа в плане реализации, «Ручной запуск
крона обучалок»):

7.1. `GET /api/cron/tutorial-scenario-generate` с заголовком
`Authorization: Bearer <CRON_SECRET>` (или кнопка «Запустить» у
джобы `tutorial-scenario-generate` на вкладке «Кроны» админки) —
нужен настоящий `GEMINI_API_KEY`/`GOOGLE_GEMINI_API_KEY` и сеть до
Gemini; при их отсутствии джоба падает целиком (осознанно, не
best-effort — см. `CronController`'s доккомментарий). Ожидаемый
результат — до 10 строк `TutorialScenario` (по числу шагов обучалки),
`costly`-сценарии остаются неодобренными до ручного решения оператора.

7.2. `GET /api/cron/tutorial-scenario-run` (или кнопка в админке) —
нужны `FIXTURE_USER_TOKEN`, `FIXTURE_TELEGRAM_ID`, `TMA_PUBLIC_URL` и
заведённый фикстурный пользователь (`npm run seed:fixture-user`).
Без них джоба должна вернуть `{skipped: "..."}`, а не упасть с 500 —
это поведение проверено НАПРЯМУЮ (не только чтением кода) в рамках
этого аудита: реальный `TutorialScenarioRunnerService.run()` был
исполнен в песочнице с фейковыми зависимостями вместо Prisma/Blob/
Notify/Ffmpeg (сама песочница не может дать ни БД, ни сеть) и
корректно вернул `{skipped: "фикстурный вход не настроен", total: 0,
passed: 0, failed: 0, outcomes: []}`, ни разу не обратившись к
заглушке Prisma. На реальном стенде с фикстурой — 10 сценариев
проигрываются headless-браузером, `lastRunStatus` каждого обновляется,
успешные дополнительно шлют кадры на сборку слайд-шоу (если настроен
`FFMPEG_API_KEY`) — итог смотреть на вкладке «Состояние данных»
`/assistant`.
