## 1. Контекст

Синтез речи в проекте — не встроенная в Veo дорожка, а отдельный шаг
постобработки (§15 SPEC, этап 35): `BrandManifest.voiceMode` переключает
`veo` (речь синтезирует сама Veo, как было до этапа 35) / `voiceover`
(наш синтез поверх ролика Veo, звук Veo уходит в фон) / `dub` (наш
синтез вместо звука Veo). При `voiceMode !== 'veo'` постобработка зовёт
провайдера синтеза после рендера — единственный сегодняшний провайдер
для этого шага — ElevenLabs.

Два независимых повода пересмотреть выбор:
1. **Цена и язык.** ElevenLabs тарифицируется кредитами, которые, по
   независимым обзорам (не проверено по счетам самого проекта —
   `AI_PRICE_ELEVENLABS`-подобной строки в `ai-pricing.ts` нет вовсе,
   стоимость синтеза сегодня в журнал расходов не попадает отдельной
   строкой — см. находку 6.1 аудита ниже), расходуются быстрее
   заявленного тарифа. Украинский язык поддержан (`eleven_multilingual_v2`),
   но не является для ElevenLabs основным рынком.
2. **Клонирование голоса для п. 32 TODO.** `AI-ACTORS-NO-REFERENCE-SPEC.md`
   §3.3 предполагает новую интеграцию с `POST /v1/voices/add`
   ElevenLabs (инстанс-клонирование), которой в проекте сегодня нет —
   это в любом случае новый код, а значит разумный момент спросить,
   тот ли это провайдер, а не писать интеграцию под инерцию выбора,
   сделанного на этапе 35 для готового каталога голосов, а не для
   клонирования.
3. **Неотличимость от живого голоса — отдельный, самый весомый
   критерий, не сводится к 1/2.** Рыночный сигнал: реальная вакансия
   студии AI UGC-рекламы прямо формулирует требование к озвучке как
   «не звучать як ElevenLabs, а як реальна людина-блогер» — то есть для
   покупателя такой рекламы узнаваемость голоса ElevenLabs уже сама по
   себе минус, независимо от цены и латентности. Это меняет вес
   критериев по сравнению с версией этого раздела, написанной для
   более общего случая «дешевле/быстрее»: см. решение в §5.2.

## 2. Что уже есть (перепроверено чтением кода)

### 2.1. Абстракция провайдера уже задумана — но не подключена как переключаемая

`backend/src/modules/tts/tts.types.ts` — интерфейс `TtsProvider`
(`configured()`, `synthesize()`, `voices()`) с доккомментарием,
дословно написанным под этот самый случай: «голос — та часть, которую
бренд захочет поменять (свой клон, **другой сервис**, свой TTS на своём
железе), и переезд не должен трогать всё остальное». Это архитектурное
намерение существует с этапа 35 — но **не реализовано как реальное
переключение**: `TtsModule` (`tts.module.ts`) регистрирует
`ElevenLabsService` как обычный провайдер NestJS и экспортирует его **по
конкретному классу**, не по токену интерфейса `TtsProvider`. Все три
потребителя (`tts.controller.ts`, `postprod.service.ts`) инжектят
`ElevenLabsService` напрямую по имени класса. Добавление второго
провайдера без выбора между ними технически возможно (просто ещё один
класс), но переключение «какой из них сейчас активен» потребует
доработки самого модуля — интерфейс это предвидел, инфраструктура
выбора — нет.

### 2.2. Форма запроса/ответа — то, что новый провайдер обязан воспроизвести

```ts
// tts.types.ts
interface SynthesisRequest {
  text: string;
  voiceId?: string | null;
  model?: string | null;
  language?: string | null;
  timestamps?: boolean; // этап 67, субтитры — см. 2.3
}
interface SynthesisResult {
  audio: Buffer;
  mimeType: string;
  characters: number;
  voiceId: string;
  model: string;
  alignment?: SubtitleAlignment;
}
type SynthesisOutcome =
  | ({ ok: true } & SynthesisResult)
  | { ok: false; skipped: true; reason: string }  // не настроено — штатно
  | { ok: false; skipped: false; reason: string }; // сломалось — ошибка
```

`skipped`/`ok: false` с разведением «не настроено» и «сломалось» —
намеренное решение `ElevenLabsService`, не часть интерфейса формально,
но соглашение, которое любой новый провайдер обязан соблюдать: ключ не
задан не должно ронять генерацию (доккомментарий `elevenlabs.service.ts:1-19`
специально это подчёркивает — «здесь нет ни одного `throw`»).

### 2.3. Пословный тайминг — используется реально, не декоративное поле

`postprod.service.ts:486-491` зовёт `synthesize({..., timestamps:
withTimestamps})`, когда включены вшитые субтитры (этап 67) и
`voiceMode !== 'veo'` — `alignment` в ответе становится входом для
`common/subtitles.ts`. Значит: **любой провайдер-кандидат обязан либо
отдавать пословный/посимвольный тайминг синтезированной речи нативно,
либо субтитры для `voiceover`/`dub` при этом провайдере придётся
интерполировать эвристикой** (как уже сделано для `voiceMode: 'veo'` —
приём есть, `voiceover-script.ts`, но с прямо признанным в SPEC §46
риском дрейфа). Это не второстепенная деталь совместимости, а
полноценный критерий выбора наравне с ценой.

### 2.4. Голос — атрибут бренда, не сессии, замораживается в снимок

`BrandManifest.voiceMode/ttsVoiceId/ttsModel` — три строковых поля,
`ttsVoiceId` ничем не помечен как принадлежащий конкретному провайдеру.
Значение копируется в `session.data.brandManifestSnapshot` при создании
сессии (§12 SPEC) и используется тем же `synthesize()` без проверки, чей
это идентификатор. Если сегодня сменить провайдера конфигом на стенде,
где уже есть бренды с заполненным `ttsVoiceId` от ElevenLabs, эти
значения станут бессмысленными для нового провайдера без единой ошибки
компиляции или валидации — тихая порча данных, не крах (см. находку 6.2
аудита).

### 2.5. Переменные окружения и админ-панель

`VOICE_API_KEY`/`VOICE_ID`/`VOICE_MODEL` — читаются `elevenlabs.service.ts`,
описаны в `env-settings.ts:496-533` (вкладка «Настройки» админки) и
`doc/DEPLOYMENT.md:157-158`. Не заданы — синтез просто пропускается
(`configured() === false`), продукт работает как до этапа 35.

## 4. Архитектурное решение

### 4.1. Реальная переключаемость провайдера — оборачивание в DI-токен, а не просто третий класс

`TtsModule` должен экспортировать `TtsProvider` **по токену**, не по
конкретному классу:

```ts
export const TTS_PROVIDER = Symbol('TTS_PROVIDER');

@Module({
  providers: [
    ElevenLabsService,
    CartesiaService,       // новый
    {
      provide: TTS_PROVIDER,
      useFactory: (eleven: ElevenLabsService, cartesia: CartesiaService) => {
        const provider = process.env.TTS_PROVIDER?.trim() || 'elevenlabs';
        return provider === 'cartesia' ? cartesia : eleven;
      },
      inject: [ElevenLabsService, CartesiaService],
    },
  ],
  exports: [TTS_PROVIDER],
})
export class TtsModule {}
```

`tts.controller.ts` и `postprod.service.ts` переходят на `@Inject(TTS_PROVIDER)
private readonly tts: TtsProvider` вместо конкретного класса — четыре
файла (см. 2.1), небольшой периметр правки. Это ровно то, что
доккомментарий `tts.types.ts` описывал с этапа 35, просто не было
доведено до конца, потому что второго провайдера не было.

### 4.2. Пометка провайдера на самом голосе — иначе находка 6.2 останется дырой навсегда

`BrandManifest` получает новое поле:

```prisma
/// Какой провайдер выпустил ttsVoiceId — без этого поля смена
/// TTS_PROVIDER на стенде делает существующие ttsVoiceId бессмысленными
/// без единой ошибки (см. doc/TTS-PROVIDER-ALTERNATIVES-SPEC.md §2.4/6.2).
ttsProvider String? // 'elevenlabs' | 'cartesia' | null — null = решается активным TTS_PROVIDER (старые записи)
```

`synthesize()` в постобработке проверяет `brand.ttsProvider` перед
вызовом: если задан и не совпадает с активным `TTS_PROVIDER` стенда —
не молча использовать чужой идентификатор голоса, а вернуть `{ok: false,
skipped: false, reason: 'голос настроен для другого провайдера синтеза'}`
(та же семантика «сломалось», что уже принята для прочих ошибок
конфигурации) — и подсказать в интерфейсе манифеста, что голос нужно
перевыбрать. Миграция для существующих записей — `ttsProvider: null`
трактуется как «голос от провайдера, который был активен на момент
записи», без ретроактивной простановки (нет надёжного способа узнать это
постфактум для уже существующих `ttsVoiceId`).

### 4.3. Клонирование (п. 32 TODO/`AI-ACTORS-NO-REFERENCE-SPEC.md` §3) — решено: Resemble, поток асинхронный

**СДЕЛАНО (этап 73).** Реализовано ровно так, как спроектировано ниже:
`ResembleService.cloneVoice()`/`getVoiceStatus()`/`deleteVoice()`,
presigned-Blob загрузка образца (не `dataset_url` по внешней ссылке —
запись сначала попадает в наш собственный Blob, тот же приём, что у
фото персонажа/сцены, и его публичный URL уже передаётся Resemble как
`dataset_url`), новый модуль `modules/user-voices/`, вебхук `POST
/voices/webhook/resemble?secret=...` (секрет в query, не заголовке —
причина та же, что предполагалась ниже) с poll-фоллбеком в `GET
/voices` для стендов без публичного HTTPS. Один нюанс не был очевиден
на этапе проектирования и найден только при реализации: `GET /voices`
у Resemble отдаёт голоса НА ВЕСЬ аккаунт, а `RESEMBLE_API_KEY` в
проекте общий на всех подписчиков — без фильтра клон одного
пользователя светился бы в каталоге `/tts/voices` у всех остальных
(закрыто в `TtsController.voices()`, подробности —
`AI-ACTORS-NO-REFERENCE-SPEC.md` §3.3).

Владелец продукта явно расставил приоритет (§5.2): критерий —
неотличимость от живого голоса, а не скорость клонирования; несколько
минут на обучение голоса — приемлемая цена за это. Решение — **Resemble
AI**, поток клонирования — **асинхронный**, не синхронный
запрос-ответ, который изначально предполагался в
`AI-ACTORS-NO-REFERENCE-SPEC.md` §3.3 по образцу ElevenLabs `/v1/voices/add`:

- `UserVoice` (модель, предложенная в `AI-ACTORS-NO-REFERENCE-SPEC.md`
  §3.4) создаётся в состоянии `TRAINING` сразу после отправки образца
  — `POST /api/v2/voices` с `name`/`language`/`dataset_url` (или
  отдельной загрузкой записей) + `callback_uri` (см. ниже), ответ —
  `{uuid, status: "pending"}`.
- Обучение занимает «под минуту» по официальной документации
  (`docs.resemble.ai/voice-creation/voices/clone-overview`,
  подтверждено 9 сентября 2026) — единый процесс на 3+ записях,
  суммарно ≈10 секунд речи. **Исправление находки, ранее бывшей в этом
  разделе**: деления «rapid ($2/мес, до минуты) / professional ($5/мес,
  ~40 минут)» в официальной документации Resemble НЕ найдено — это
  было утверждение вторичного источника (`checkthat.ai`), которое не
  подтвердилось при более внимательном чтении `docs.resemble.ai` перед
  реализацией. Открытый вопрос 5.2б ниже переформулирован с учётом
  этого.
- Готовность голоса определяется **вебхуком** (`callback_uri` в теле
  запроса создания голоса, payload `{"ok": true, "id": "voice-uuid",
  "status": "finished"}`) — подтверждено официальной документацией, не
  предположение; поллинг поля `status` голоса — рабочая альтернатива,
  если вебхук неудобен на конкретном стенде (см. §5.4, вопрос закрыт).
- Синтез (`POST https://f.cluster.resemble.ai/synthesize`) принимает
  `project_uuid` **как необязательное** поле — оно нужно только для
  того, чтобы Resemble сам организовал сгенерированный клип в «проект»
  в своём личном кабинете; для синтеза без сохранения в кабинете (а
  именно так работает текущий пайплайн — аудио сразу уходит в наш
  Blob, см. §2.2) это поле можно не передавать вовсе. Это закрывает
  архитектурный вопрос, всплывший при исследовании перед этим этапом:
  сторонняя Python-обёртка над Resemble SDK использует другой,
  managed-эндпоинт (`clips.create_sync` из Clips API), где
  `project_uuid` обязателен — но это не тот эндпоинт, который выбран
  для интеграции (см. §3, «Синтез, эндпоинт»); прямой `/synthesize`
  проекта не требует.

**Следствие для `AI-ACTORS-NO-REFERENCE-SPEC.md` §3.3/§3.4 — СДЕЛАНО:**
тот раздел описывал синхронный поток по образцу ElevenLabs и был
переписан на асинхронный этапом 73, вместе с реализацией самого п. 32
(§3.3/§3.4/§3.6 того документа отражают то, что реально построено, не
первоначальный черновой план).

## 5. Открытые вопросы владельцу продукта

5.1. **Заменить ElevenLabs целиком или добавить как второй провайдер
   рядом.** Архитектура §4.1 поддерживает оба варианта одинаково дёшево
   (это и есть смысл DI-токена) — вопрос коммерческий и по риску
   (полная замена — один провайдер, меньше кода поддержки, но и полная
   зависимость от него; два провайдера — можно тестировать на части
   трафика, но следующий этап §4.2/данные усложняются на оба сразу).

5.2. **Решено: Resemble AI, не Cartesia.** Приоритет владельца продукта
   явно сформулирован — «нужно именно неотличимо от реального голоса,
   обучение в несколько минут это нормально». Это делает решающим ровно
   тот критерий, у которого в таблице §3 количественная опора есть
   только у одного провайдера: опубликованные слепые тесты Chatterbox
   против ElevenLabs (65,3% побед по естественности). У Cartesia такой
   оценки нет вовсе — независимые сравнения прямо описывают её как
   инструмент, где реализм принесён в жертву задержке (позиционирование
   под голосовые агенты/телефонию, не под контент), то есть по
   заявленному критерию она, вероятно, не только не выигрывает у
   ElevenLabs, а уступает и ему тоже. Раз задержка обучения (минуты, не
   миллисекунды) явно объявлена приемлемой, единственное реальное
   преимущество Cartesia (синхронность) перестаёт быть аргументом.
   **Cartesia остаётся в этом документе как альтернатива на будущее**
   — see 5.2а — не как отменённая идея, а как решение для другой
   задачи, которую сегодняшний приоритет не ставит.

   5.2а. **Когда возвращаться к Cartesia.** Если/когда у продукта
   появится задача, где важна именно скорость, а не финальный реализм
   (живой стриминг ответа AI-агента пользователю, интерактивный
   предпросмотр голоса «на лету» с задержкой меньше произносимой фразы)
   — архитектура §4.1 (DI-токен) уже допускает добавить её вторым
   провайдером без переписывания первого. Формулировка задачи «сделать
   под Cartesia» без такого повода не имеет смысла при нынешнем
   приоритете — она отвечает на другой вопрос, не на «неотличимо от
   блогера».

   5.2б. **Снят как открытый вопрос (9 сентября 2026) — деления
   rapid/professional на уровне API не существует.** Официальная
   документация (`docs.resemble.ai/voice-creation/voices/create`,
   `.../clone-overview`) описывает единый процесс клонирования: 3+
   записей суммарно ≈10 секунд, обучение «под минуту», без параметра,
   выбирающего между «быстрым» и «профессиональным» качеством. Более
   длинный/качественный образец (десятки минут речи) можно передать
   тем же `dataset_url`, но это не отдельный режим API, а просто больше
   исходных данных для того же эндпоинта. Реализация не выбирает между
   двумя путями — путь один; вопрос «сколько речи присылать по
   умолчанию в UI п. 32» остаётся продуктовым (соответствует
   заявленному в `AI-ACTORS-NO-REFERENCE-SPEC.md` §3.2 сценарию «минута
   речи» — этого достаточно с большим запасом относительно
   десятисекундного минимума API), но это UX-вопрос, не архитектурный.

5.3. **Проверить нативную поддержку тайминга у Resemble для
   субтитров — уже подтверждено, действие не требуется.** В отличие от
   версии этого вопроса до решения 5.2 (когда рассматривался Cartesia,
   чей тайминг не проверялся), выбранный провайдер — Resemble — уже
   подтверждён чтением документации: `audio_timestamps` приходит
   нативно в том же ответе `synthesize()` (§3, таблица), отдельный
   вызов не нужен. Открытый вопрос закрывается решением 5.2, отдельного
   действия перед реализацией здесь больше нет.

5.4. **Закрыт (9 сентября 2026) — вебхук есть, подтверждено
   официальной документацией.** `POST /api/v2/voices` принимает
   `callback_uri`; Resemble сам стучится на него при готовности
   (`{"ok": true, "id": "voice-uuid", "status": "finished"}`). Поллинг
   `status` — рабочая резервная альтернатива для стендов без
   публичного HTTPS-эндпоинта для вебхука (dev-окружение). Раз
   обучение «под минуту» (§4.3/5.2б) — воркер по образцу §65-68
   избыточен для п. 32: клонирование в главную очередь крон-воркеров
   ставить не нужно, достаточно (а) отправить запрос с `callback_uri`,
   (б) держать `UserVoice.status: TRAINING` до прихода вебхука ИЛИ (в)
   как фоллбек — короткий поллинг с ограниченным числом попыток при
   следующем обращении пользователя к экрану клонирования (без
   отдельного крона).

5.5. **Закрыт исправлением находки 6.1 (9 сентября 2026).** Расход на
   синтез уже логируется в `ai_usage` для ElevenLabs
   (`postprod.service.ts:507-512`, `tts.controller.ts:136-141`) и уже
   переводится в деньги (`ai-pricing.ts` — ключ `'elevenlabs-tts'`).
   Открытого вопроса тут больше нет — задача для реализации сузилась до
   «завести параллельный ключ `'resemble-tts'` с реальной ставкой
   Resemble и перестать хардкодить `model: 'elevenlabs-tts'` в двух
   местах вызова» (см. находку 6.1, п.6 списка файлов §6).

### Находка 6.2 (высокая — архитектурный риск ТЗ, не находка в существующем коде). §4.2 — единственная защита от порчи `ttsVoiceId` при смене провайдера держится на дисциплине заполнения нового поля, а не на структуре данных

`ttsProvider: String?` — необязательное поле. Ничто в схеме не мешает
оставить его `null` для новых записей и получить тот же тихий разрыв,
который §4.2 должен был закрыть: голос от Cartesia с `ttsProvider: null`
на стенде, переключённом на `TTS_PROVIDER=elevenlabs`, будет
интерпретирован как «старая запись, провайдер на момент записи», хотя
на самом деле это НОВАЯ запись без проставленного поля. Правильнее —
делать поле обязательным (`String`, не `String?`) для всех НОВЫХ записей
через сервисный слой (`BrandManifestService.updateVoice()` заполняет его
всегда сам, не полагаясь на клиента), а `null` в схеме оставлять только
как факт миграции существующих строк, а не как валидное состояние для
новых. Текст §4.2 выше это не проговаривает явно — стоит поправить перед
переводом этого ТЗ в план реализации.

### Находка 6.3 (низкая, про источники самого ТЗ, не про продукт). Официальная страница цен Resemble AI на момент проверки (сентябрь 2026) описывает не тот продукт

`resemble.ai/pricing` при прямой проверке во время написания этого ТЗ
показывает тарифы на детекцию дипфейков (аудио/видео/изображения) —
TTS/клонирование в цифрах $0.0005/сек и $2–5/мес за голос,
использованные в таблице §3, взяты со вторичного источника
(`checkthat.ai/brands/resemble-ai/pricing`), не с первой стороны.
Компания, судя по всему, за последнее время сместила акцент своей
публичной страницы цен на другой продукт (детекция синтетического
контента) — сам TTS/клонирование, вероятно, ушёл в отдельный
раздел/личный кабинет без публичной страницы, но это не проверено до
конца. **Перед реализацией с Resemble — обязательно перепроверить
актуальную цену из личного кабинета, а не из этого ТЗ** — риск
устаревания здесь выше, чем у Cartesia, где официальная `cartesia.ai/pricing`
проверена напрямую.

### Находка 6.4 (закрыта решением владельца продукта — 9 сентября 2026). Непроверенный тайминг Cartesia больше не блокирует §5.2, потому что Cartesia больше не рассматривается по этому критерию

Изначальная версия находки (см. историю документа) была верна для
черновика §5.2, рекомендовавшего Cartesia без взвешивания критерия
реализма. После явного приоритета «неотличимо от реального голоса»,
поставленного владельцем продукта, решение 5.2 больше не опирается на
Cartesia вовсе — вопрос о её тайминге стал неактуален для текущего
выбора (Resemble, чей тайминг как раз подтверждён — §3 таблица). Находка
остаётся в документе как показатель того, что первая версия §5.2
опиралась на неполный набор критериев — сам процесс аудита сработал
как задумано (нашёл пробел до реализации, не после).

### Находка 6.5 (средняя, новая — обнаружена перед реализацией 9 сентября 2026). Публичный каталог голосов Resemble заметно меньше, чем `/v1/shared-voices` ElevenLabs — `GET /tts/voices` для Resemble вернёт мало вариантов до накопления клонов

`docs.resemble.ai/voice-creation/voices/list` подтверждает параметр
`pre_built_resemble_voice` — то есть готовые (не клонированные) голоса
у Resemble есть. Но независимый обзор (aiindigo.com, 2026) описывает их
как «несколько стоковых голосов» на бесплатном тарифе — формулировка,
указывающая на маленький список, не на каталог из сотен голосов, как у
ElevenLabs `/v1/shared-voices`. Точное число официальной документацией
не подтверждено (не нашлось отдельной страницы с перечнем).

Следствие для реализации: `ResembleService.voices()` должен вызывать
`GET /api/v2/voices` **без специального различения** pre-built/custom
(тот же приём, что уже сегодня `ElevenLabsService.voices()` — просто
отдаёт всё, что видно по ключу API, с пояснением, если список пуст) —
никакой дополнительной логики "показать только готовые" не требуется,
это тот же паттерн, что уже есть. Но экран выбора голоса бренда после
переключения на Resemble предсказуемо покажет заметно меньше вариантов,
чем показывал ElevenLabs, пока оператор аккаунта не наклонирует голоса
сам (через п. 32, если он реализован, либо вручную через кабинет
Resemble) — это не баг реализации, а свойство самого Resemble,
которое стоит явно показать оператору при первом переключении (тот же
принцип, что уже применён к `error` в `VoiceCatalogueResponse`, когда
список голосов пуст или короткий).

  акцент на задержке, не на выразительности), так что предвзятость
  источника вряд ли исказила именно это направление вывода.
- Обязательность `project_uuid` на эндпоинте синтеза — проверена
  прямым чтением `docs.resemble.ai/api-reference/text-to-speech/synthesize`
  9 сентября 2026: поле необязательное, нужно только для организации
  клипов в личном кабинете Resemble; ложная тревога, поднятая при
  чтении исходников сторонней Python-обёртки (та использует другой,
