# QA платформы: повторный аудит и отчётность — 20.10.2026

## Вывод

Работающий QA MVP покрывает каталог/версии, планы/окружения, ручные и импортированные прогоны, OIDC-доставку GitHub CI, замечания с происхождением, приватные PNG, mock-стенды и сверку форм. Это ещё не автоматический аудит произвольного сайта и не полная TMS. Проверка рекламного входа выявила отсутствие самостоятельного быстрого отчёта; он добавлен как **локальный аудит открытой страницы**, с явными границами.

## Проверенная область

- `sites-backend/src/modules/qa-catalog`, `qa-stands`: доступ viewer/admin, изоляция аккаунтов, версии/CAS, replay/идемпотентность, импорт runner/attempts, планы, inventory, PNG/retention, внешнее доказательство приёмки.
- `assist`: каталог/CSV, планы/прогоны, замечания/source/fix prompt, mock/OpenAPI и формы; права и ошибки API. Исправления не повышают роль viewer.
- `tools/form-capture`: временный activeTab, отсутствие постоянного host grant, структура без значений, изолированная панель, локальный перенос и защита от повторов. Тестовый host grant в E2E не равен настоящему toolbar activeTab.
- `.github/workflows/sandbox-daily.yml`, доставка отчётов и последние scheduled результаты. Старые TODO сверены с фактической реализацией.

Это чтение кода и целевые проверки, не новая полная приёмка каждого экрана платформы/мобильных клиентов на проде. Прежняя живая приёмка viewer/activeTab 20.10 сохранена отдельно в TODO.

## Находки и исправления

### QA-R1 — противоречивый статус карточки (S2)
Сводка правильно блокировала passed при неуспешном automated runner, но «Текущий результат» показывал исходный passed. Вынесен `qaAcceptanceStatus`; одна функция используется в карточке, сводке и отчёте. Исходный статус не переписывается; failed/skipped/blocked и отсутствие попытки сохраняются.

### QA-R2 — нет пригодного для передачи отчёта запуска (S3 / продуктовый пробел)
Добавлено скачивание Markdown по свежему GET: ID сайта/запуска, ревизия, версии кейсов, последние попытки и комментарии, итог для приёмки отдельно от исходного статуса, контекст плана/окружения, проект и tested/deployed SHA с явным «не подтверждён». Выгрузка не создаёт сущностей, доступна QA viewer. При ошибке обновления файл не выдаётся как свежий. При несохранённом черновике кнопка выключена.

Текст Markdown экранируется. История и приватные URL артефактов не включены. Сохранённые комментарии могут содержать сведения пользователя — перед передачей это нужно проверить. Это отчёт выбранных кейсов, не сертификат сайта. Реестр findings с доказательствами/PDF остаётся отдельным этапом.

### QA-R3 — отсутствует быстрый самостоятельный рекламный вход (продуктовый пробел)
Q 0.2.4: «Проверить открытую страницу» и локальное скачивание `.md`. Шесть проверок: title, lang, viewport, очевидные подписи видимых полей, alt видимых изображений, повторяющиеся ID. Результат — числа сигналов, рекомендации, origin и время. Нет чтения значений полей, образцов текста страницы, URL-пути, сетевых вызовов, AI или оплат. Никакой отправки форм/создания findings. Повтор не создаёт второй панель/сущности.

Это эвристики: «сигнал не найден» не равно отсутствию дефектов. Не проверяются бизнес-логика, отправка форм, безопасность, сеть/performance, контраст, клавиатура, iframe/Shadow DOM, другие страницы и состояния. Предусмотрен предел размера DOM. Полный аудит сайта по URL не реализован и не обещается. В каталоге QA добавлены вход, архив и инструкция установки; разрешения расширения не расширены.

### QA-R4 — неточная подпись источника (S3)
История называла каждый автоматический результат Playwright, хотя сервер принимает также Jest. Подпись истории заменена на «Автотесты»; происхождение/SHA/runner остаются доступны. UI импорта по-прежнему описывает свой пользовательский Playwright-формат, серверный Jest CI не менялся.

## Проверки

- Сервер: **260/260 тестов, 26 suites**, настоящий изолированный Docker PostgreSQL/pgvector, все **52 миграции** применены. В том числе database acceptance каталога, артефактов, планов, inventory и стендов; production-база не использовалась.
- Расширение: **4/4 unit, 11/11 Chromium E2E**. Новый сценарий проверяет реальный установленный пакет, отчёт/скачивание, неизменность значений и отсутствие новых запросов/дублей. Остальные сценарии проверяют отказ без grant, capture/transfer и drift. Архив и сгенерированная панель сверены с исходниками.
- Assist: 70 тестовых скриптов, typecheck, lint; production build. Новая регрессия проверяет blocked runner, исходный passed, неизвестный SHA, escaping, отсутствие попыток и успешный запуск.
- Ежедневный QA: schedule [18.10](https://github.com/tarasenkoandriii/viral4creators/actions/runs/39122683018), [19.10](https://github.com/tarasenkoandriii/viral4creators/actions/runs/39260799281), [20.10](https://github.com/tarasenkoandriii/viral4creators/actions/runs/39417464793) — success. 20.10: 13 browser passed, desktop/mobile отчёты доставлены; локальные voice-модели 64 + 11 + 4 проверки. Платная Soniox-джоба skipped, не passed. Новые платные запуски не инициировались.

1. Выкладка и production-проверка новых кнопок и архива 0.2.4. Прежняя приёмка viewer/activeTab относится к версии 0.2.3, не является доказательством новой версии.
2. Полный аудит нескольких страниц/состояний по URL, ручной бизнес-сценарий, снимки/доказательства и повторный аудит после исправлений.
3. Общий клиентский отчёт findings: приоритет/влияние, приватные артефакты, регрессии; PDF и управляемая публичная выдача.
4. Реальные Telegram iOS/Android, cross-browser; расширенная TMS (реестр требований, shared steps, missing shards, JUnit/GitLab/issue/PR-интеграции).
5. Публичный рекламный сценарий и измерение заявок — после приёмки; никаких новых публикаций/UTM/трафика в этом проходе.

Nova, принятый Tutorial, Greeting-эталон, семейные ролики и платные генераторы не изменялись. Production кейсы/приглашения/прогоны/замечания не создавались.
