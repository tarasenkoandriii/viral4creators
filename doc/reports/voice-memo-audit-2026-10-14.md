# Сквозная проверка голосового управления и мемо — 14.10.2026

Итог: автоматические проверки исполнения зелёные, сухая проверка многошагового мемо после исправлений прошла, версия опубликована для теста. Полное живое исполнение ещё не подтверждено; UK-провайдерный прогон не прошёл из-за Gemini 503. Это не аппаратная приёмка реальных микрофонов.

## Свежие автоматические результаты

- Sites-backend: 47 наборов, 571 тест прошёл; 16 наборов / 17 тестов пропущены без локального SITES_DIRECT_URL. Это пропуски, а не успешная локальная приёмка БД.
- Backend генератора: 44 набора, 767 тестов голосовой подсистемы прошли.
- Frontend: 64 сценария Silero VAD, 11 runtime-проверок и 4 проверки lifecycle прошли.
- Клиентские скрипты frontend/assist/widget по voice/memo/soniox прошли, включая API мемо, шаблоны, Tutorial и goal.
- Браузерный Chromium, локальный тестовый API: 43 проверки цепочек, компенсаций, voice-control и admin-voice прошли. Покрыты подтверждения, Esc/стоп/клик человека, запреты, подмена кнопки, CSP, отсутствие повторного шага после перезагрузки. Локальный mock не заменяет живой backend и устройства.

## Настоящие RU/UK провайдеры

Начальные RU и UK проверки assistant TTS → Soniox STT → voiceTicket → assistant остановились на HTTP 502 в chat-seed, до синтеза. Диагностический запрос позже вернул 200. Отдельный повтор RU прошёл полностью, без автоматических retries. Отдельный повтор UK снова остановился на 502 в chat-seed.

В production-логах assist-api подтверждены upstream Gemini ApiError 503 и один AbortError/таймаут. Это не подтверждённый billing-сбой и не доказательство ошибки Soniox: синтез/распознавание в неуспешных прогонах ещё не начинались. Успешный RU не отменяет нестабильность. Дефолт Resemble Nova `a9fc5a41` не менялся; существующая отдельная конфигурация Soniox TTS sandbox не изменялась.

## Живое мемо как сценарий

С согласия владельца sandbox временно переведён из off в test; публичный режим on не включался. Создано только собственное тестовое М-1. Минимальный первоначальный шаг заменён шестишаговой цепочкой: имя → email → тема → комментарий → отметка о вымышленных данных → единственная отправка. Значения полей — слоты, не сохранённые пользовательские credentials. Фразы вызова RU/UK; цель «Тестовая заявка принята. Отправка отключена.»; listed выключен.

Версия собрана и получена одноразовая ссылка проверки. Сухой прогон обнаружил цели, но не текст итогового сообщения. После ручной синтетической отправки сообщение присутствовало на странице; повторный сухой прогон всё равно не увидел цель, итог — fail. Источник: `memoCheckPage` проверяет text goal по snapshot.title и snapshot.elements[].text; обычный paragraph с role=status отсутствует в интерактивном снимке. Поэтому публикация и живое исполнение мемо не подтверждены. Подменять бизнес-результат наличием кнопки отправки нельзя.

Устранение требует отдельного безопасного чтения результата/пассивных статусов для проверки цели, с маскированием ПД и исключением запрещённых/UGC-зон; нельзя объявлять статусы кнопками либо расширять возможность кликов ради прохождения приёмки. Нужна регрессия: пустой статус — missing, фактический результат — ok, запрещённые зоны не читаются, динамический текст не становится исполняемой целью.

После проверки режим sandbox возвращается в off; тестовое мемо остаётся непубличным для повторной приёмки. Тестовые заявки не уходят людям и не записываются в рабочую базу.

## Исправление редактора

При сохранении шага пользователь мог редактировать поля, затем асинхронный ответ стирал эти правки. Также изменение listed/шага сбрасывало ранее введённые несохранённые имя/фразы/цель. В MemoCard поля блокируются на время запроса; операции над шагами/видимостью сохраняют локальный edit, он очищается после явного успешного сохранения черновика. Сборка и lint проверены локально. Production-приёмку исправления фиксировать отдельно после выкладки.

## Исправление пассивного результата

Добавлено opt-in чтение до 10 видимых `role=status` сообщений, до 160 символов каждое, только по запросу сухого прогона мемо. Обычный план/снимок эти сообщения не собирает. Запрещённые, UGC, скрытые зоны и поля исключаются до отправки; email/телефоны/секреты маскируются повторно на сервере. Чтение клона не меняет живой DOM. Статусы не получают ref и не становятся целями исполнения. Серверный memoCheckPage учитывает их только при проверке text goal.

Серверные регрессии: пустой результат missing, появившийся статус ok, лимиты и маскирование; 34 теста мемо/целей прошли. Реальный Chromium проверяет opt-in, защищённые/скрытые зоны, маскирование email, неизменность DOM и отсутствие статуса среди исполняемых elements. Production-приёмка этого исправления ещё требуется.

Уточнение выкладки: начальная реализация чтения статусов превысила act gzip-бюджет. Чтение вынесено в уже существующий ленивый `check.js`; подтверждены act 8,96 КБ / 9 КБ, undo 1,84 / 2 КБ, check 3,53 / 6 КБ. Полный size-check, build, lint и Chromium regression прошли. Мастер показывает номера не прошедших шагов, не раскрывая значения полей.

Повторный живой прогон дополнительно выявил потерю аргумента `statuses` в адаптере chat controller и неверный dry-check пример `x` для select-слота. Адаптер передаёт opt-in дальше; для списка без фиксированного значения dry-check берёт существующую опцию, не изменяя слот и не исполняя выбор. Фиксированные значения по-прежнему проходят обычную проверку допустимости. Добавлена серверная регрессия, 14 тестов целей прошли.

## Итог текущего прохода

Сухая приёмка шестишагового М-1 и текстовой цели в production прошла; версия 1 опубликована только для собственного sandbox, listed=false. Исправлены пассивное чтение результата, передача флага через адаптер, select sample, совместимость обычного ui-snap и memos-признак отдельной тестовой сессии.

Полное исполнение, отказ/стоп и отсутствие повторной отправки остаются незакрытой живой приёмкой.

Sandbox возвращён в off; реальные клиенты и их настройки не изменялись. Nova сохранён. Proof: `outputs/memo-six-step-dry-pass-2026-10-14.png` рабочего задания. Последняя функциональная версия `05b2faf`; backend-проверка `c2e4347` в CI #38592227338 завершилась успешно, а общий прогон был отменён следующей выкладкой. ## Повтор UK после безопасной диагностики

После коммита `8070fac` повторён настоящий UK roundtrip без дополнительных повторов тестового раннера. Результат: HTTP 502 на `chat-seed`, до TTS и STT. Production-журнал того же запроса содержит `ApiError status=503` (timestamp 1791996239764). Это подтверждённая недоступность Gemini в данном прогоне, а не подтверждённый отказ Soniox. В SiteChatModel уже предусмотрены два ограниченных повтора 503 до первого ответа, без повторного воспроизведения полученных частей ответа. Увеличение числа платных запусков и смена модели не выполнялись.

GeminiText теперь сохраняет только проверенный HTTP-код ошибки вместо произвольного имени ошибки SDK; тело, промпт и ключи не журналируются. Все 10 тестов GeminiText и ESLint прошли, включая регрессию безопасности журнала. Для предыдущего отказа planner причина остаётся неподтверждённой: 503 чата не подменяет диагностику отдельного ui-plan. Режим sandbox повторно проверен в кабинете: off. Автоматическое исполнение М-1 и UK-приёмка остаются открытыми.


GeminiText дополнительно получил максимум два повтора только явного HTTP 503 (паузы 1/2 секунды), в пределах единого исходного таймаута. Изменение распространяется на потребителей GeminiText, включая planner; ответы empty/truncated, квоты и другие ошибки не повторяются. 14 тестов подтверждают предел попыток, отмену ожидания таймаутом, сохранение расхода пустого ответа и безопасность диагностики. Это устойчивость к краткому отказу, а не доказательство успешного живого исполнения мемо.
