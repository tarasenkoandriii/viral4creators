# Сквозная проверка голосового управления и мемо — 14.10.2026

Итог: автоматические проверки исполнения зелёные, но полную production-готовность объявлять нельзя. Живое многошаговое мемо не опубликовано из-за ограничений проверки текстовой цели; UK-провайдерный прогон не прошёл из-за Gemini 503. Это не аппаратная приёмка реальных микрофонов.

## Свежие автоматические результаты

- Sites-backend: 47 наборов, 571 тест прошёл; 16 наборов / 17 тестов пропущены без локального SITES_DIRECT_URL. Это пропуски, а не успешная локальная приёмка БД.
- Backend генератора: 44 набора, 767 тестов голосовой подсистемы прошли.
- Frontend: 64 сценария Silero VAD, 11 runtime-проверок и 4 проверки lifecycle прошли.
- Клиентские скрипты frontend/assist/widget по voice/memo/soniox прошли, включая API мемо, шаблоны, Tutorial и goal.
- Браузерный Chromium, локальный тестовый API: 43 проверки цепочек, компенсаций, voice-control и admin-voice прошли. Покрыты подтверждения, Esc/стоп/клик человека, запреты, подмена кнопки, CSP, отсутствие повторного шага после перезагрузки. Локальный mock не заменяет живой backend и устройства.

## Настоящие RU/UK провайдеры

Начальные RU и UK проверки assistant TTS → Soniox STT → voiceTicket → assistant остановились на HTTP 502 в chat-seed, до синтеза. Диагностический запрос позже вернул 200. Отдельный повтор RU прошёл полностью, без автоматических retries. Отдельный повтор UK снова остановился на 502 в chat-seed.

В production-логах assist-api подтверждены upstream Gemini ApiError 503 и один AbortError/таймаут. Это не подтверждённый billing-сбой и не доказательство ошибки Soniox: синтез/распознавание в неуспешных прогонах ещё не начинались. Успешный RU не отменяет нестабильность. Дефолт Resemble Nova `a9fc5a41` не менялся; существующая отдельная конфигурация Soniox TTS sandbox не изменялась.

## Живое мемо как сценарий

С согласия владельца sandbox временно переведён из off в test; публичный режим on не включался. Создано только собственное тестовое М-1. Минимальный первоначальный шаг заменён шестишаговой цепочкой: имя → email → тема → комментарий → отметка о вымышленных данных → единственная отправка. Значения полей — слоты, не сохранённые пользовательские credentials. Фразы вызова RU/UK; цель «Тестовая заявка принята. Отправка отключена.»; listed выключен.

Версия собрана и получена одноразовая ссылка проверки. Сухой прогон обнаружил цели, но не текст итогового сообщения. После ручной синтетической отправки сообщение присутствовало на странице; повторный сухой прогон всё равно не увидел цель, итог — fail. Источник: `memoCheckPage` проверяет text goal по snapshot.title и snapshot.elements[].text; обычный paragraph с role=status отсутствует в интерактивном снимке. Поэтому публикация и живое исполнение мемо не подтверждены. Подменять бизнес-результат наличием кнопки отправки нельзя.

Устранение требует отдельного безопасного чтения результата/пассивных статусов для проверки цели, с маскированием ПД и исключением запрещённых/UGC-зон; нельзя объявлять статусы кнопками либо расширять возможность кликов ради прохождения приёмки. Нужна регрессия: пустой статус — missing, фактический результат — ok, запрещённые зоны не читаются, динамический текст не становится исполняемой целью.

После проверки режим sandbox возвращается в off; тестовое мемо остаётся непубличным для повторной приёмки. Тестовые заявки не уходят людям и не записываются в рабочую базу.

## Исправление редактора

При сохранении шага пользователь мог редактировать поля, затем асинхронный ответ стирал эти правки. Также изменение listed/шага сбрасывало ранее введённые несохранённые имя/фразы/цель. В MemoCard поля блокируются на время запроса; операции над шагами/видимостью сохраняют локальный edit, он очищается после явного успешного сохранения черновика. Сборка и lint проверены локально. Production-приёмку исправления фиксировать отдельно после выкладки.

## Открытая приёмка

1. Исправить проверку пассивного текстового результата и пройти живой шестишаговый сценарий: подтверждение, отказ, остановка на середине, отсутствие повторной отправки, проверяемый итог.
2. Подтвердить UK-провайдерный roundtrip при доступном Gemini; сохранять неуспешные прогоны и причины, не маскировать их retries.
3. Реальная админка: полный lifecycle мемо и права сотрудников, отдельные подтверждения write.
4. Android/iOS/Telegram WebView, микрофоны, шум, разные голоса. Синтетические WAV/VAD этого не доказывают.
5. Реальный worker-прогон мемо и регулярный cron с отчётом; наличие работающего VPS само по себе не закрывает этот пункт.
