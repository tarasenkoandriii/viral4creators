# Аудит SEC — безопасность и надёжность `ffmpeg-server/` (21.10.2026)

Код не правился. Пробы лежат в `/tmp/ffa-SEC/`: `p1-parse.js` (парсер), `p2-exec.js` (настоящий Executor и ffmpeg 6.1.1). Сборка для проб — `/tmp/ffa-SEC/dist`.

## Итог
- Находок S0: 0, S1: 1, S2: 1, S3: 1. Подробности — в `SEC-findings.csv`.
- Аудит неполный. Многие пункты из задания не проверены, список ниже.

## S1 — FF-SEC-01. Обход командной песочницы через ключ опции фильтра с `/`
В ffmpeg 6.1 запись `/опция=путь` в фильтрграфе означает «загрузить значение опции из файла». Это проверено в песочнице на ffmpeg 6.1.1.

Почему проходит:
- `parseFilterOptions` считает `/` допустимым символом ключа (`isKeyChar`).
- Проверка опций построена как denylist (`FILTER_FORBIDDEN_OPTIONS`). Поэтому ключи `/text`, `/file`, `/force_style` не распознаются ни как запрещённые, ни как файловые.
- `validateStepArgv` в executor отвергает только аргументы, которые *начинаются* с `/`. Значение `-vf drawtext=/text=/abs/path` он пропускает.

Что подтверждено пробой через настоящий executor (outcome=succeeded):
- **Чтение.** `drawtext=/text=../../<другая задача>/outputs/private.txt` выводит содержимое чужого файла в кадр. Кадр побайтово совпал с эталоном, где этот текст задан напрямую.
- **Запись.** `metadata=mode=print:/file=inputs/p.txt` берёт путь для записи из содержимого входа. Файл соседней задачи был перезаписан и стал пустым.

Последствия: нарушено требование ТЗ §6. Executor может прочитать любой файл, доступный uid 10001, и записать в любые монтирования, где у него есть права на запись. Это служебные файлы `.executor/` (heartbeat, capabilities) и остатки workspace других задач. Межтенантный риск сейчас ограничен тремя вещами: у executor нет сети и секретов, workspace задачи удаляется после завершения (`dispatcher.ts` ~1184), concurrency=1. Если появятся сторонние клиенты, concurrency>1 или будут оставаться входы для повтора (`retry_inputs_from`), класс нужно поднять до S0.

Исправление:
1. Отвергать любой ключ опции, начинающийся с `/`.
2. Перейти на allowlist ключей по каждому фильтру, собранный из корпуса.
3. Добавить регрессионные тесты.

## S2/S3 (кратко)
- FF-SEC-02: парсер принимает `scale=100000:100000` и `color=s=30000x30000`. Профиль §9 проверяется только для входов. Сдерживают это лишь mem_limit, дедлайн и лимит записи.
- FF-SEC-03: `-stream_loop -1` и `-loop 1 -t 999999` останавливаются только дедлайном.

## Проверено и корректно
- Парсер отвергает: `movie`, в том числе через экранирование `mo\vie`; `drawtext textfile`; `subtitles` с абсолютным путём и с `filename=` вне manifest; спрятанный через экранирование `,movie`; `;movie` внутри `-vf`; `-report`, `-progress`, `-dump_attachment`; `-i file:`, `concat:`, `inputs/../..`; выход в `/dev/null`; `%` в имени результата.
- Принудительно добавляются `-protocol_whitelist file,pipe`, `-format_whitelist` и ограничение потоков. ffprobe входов запускается в executor с whitelist форматов, допустимые форматы входов ограничены (`probe/limits.ts`), проверяются поворот, SAR и признаки decompression bomb.
- Compose: у executor `network_mode: none`, read_only, `cap_drop: ALL`, no-new-privileges, uid 10001, `cpus: 2`, `mem_limit`/`memswap_limit: 3g`, `pids_limit: 128`, `init: true`, нет env_file, Docker socket и портов, `traefik.enable=false`. У api: только `expose`, лимиты 256m / 0.5 CPU, Traefik по Host. Каталог outputs вынесен в отдельный volume, executor его не монтирует.
- В downloader есть таблица запрещённых диапазонов (0/8, частные сети, 240/4, IPv4-mapped), лимит 3 redirect, подключение к заранее проверенному адресу через свой `lookup` и SNI `servername`. Подтверждено только чтением кода.

## Не проверено
Пробы в этих областях не запускались: SSRF вживую (rebinding, разные записи IP, gzip, slowloris), убийство группы процессов при cancel/timeout, API и идемпотентность (50 параллельных POST, 409, by-key, 404/503), токены файлов, Range и path traversal, логи, шифрование и HMAC, recovery и сбои (kill на разных стадиях, второй executor, потеря БД), лимиты §9 по отдельности, лицензии в `docs/COMPATIBILITY.md`. Их нужно передать отдельным проходом.
