## Исправления

1. У assist-api отсутствовал BLOB_READ_WRITE_TOKEN. Создано и подключено отдельное приватное хранилище assist-browser-private в production, backend перевыпущен. Публичное хранилище для клиентских кадров не использовалось.
2. Публичный статус done появлялся до сохранения результата продуктовым обработчиком. `{pending:true}` попадал в представление снимка, GET завершался 500. В `BrowserJobsService.toView` промежуточный результат теперь выдаётся как running/result=null/finishedAt=null. Два регрессионных теста прошли. Выпущено в main 7353878 и deployment assist-93gn9s7zf-sibionics-ai.vercel.app.
3. На VPS применён актуальный bootstrap --update: fail2ban sshd/systemd active, установлен /etc/cron.d/bworker-watch раз в 5 минут. Docker HEALTHCHECK прошёл, контейнер healthy, lastError=null. После ручной проверки в 17:08:50 UTC сторож самостоятельно обновил статус в 17:10:01 UTC — расписание проверено фактически. В /var/lib/bworker/first-job записана первая задача. Две первоначальные ошибки сохранены в журнале, счётчики не обнулялись ради зелёного статуса.
4. Env-only redeploy был отменён штатным ignored-build. Для одного выпуска использован VERCEL_FORCE_BUILD=1; после Ready временная переменная удалена.

## Расписания и границы

Docker проверяет здоровье раз в 30 секунд; локальный сторож раз в 5 минут восстанавливает контейнер по ограниченной политике, без новых AI-задач. GitHub Sandbox daily QA запланирован на 06:17 UTC (09:17 по Киеву на дату проверки), следующий запуск использует тот же deployed sandbox. Автотест дескрипторов через assist-analytics-run требует опубликованную карту и голосовой режим не off; для этого sandbox карта есть, режим пока off, поэтому такой ежедневный автотест не заявляется включённым. Его ручная сверка на втором VPS прошла.

Центральный dashboard здоровья, аварийные уведомления и многодневная стабильность остаются отдельной приёмкой. Один успешный запуск их не заменяет. Проверки physical iOS/Android, пользовательских credentials, платных/удаляющих операций и failover внешних провайдеров в этом проходе не выполнялись.
