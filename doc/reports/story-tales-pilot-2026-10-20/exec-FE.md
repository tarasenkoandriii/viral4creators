# ST3 · пакет FE — отчёт

## Решения
- Р-ST3-FE-1: строки Story прохода 3 — в словарях `frontend/src/dictionaries/*.json`, секция `storyTales` (ru/uk/en/de/es); числовые формы — объектами LDML (тест паритета их понимает). Старый мастер Story остаётся по-русски (вне объёма).
- Р-ST3-FE-2: доступ грузит `App.tsx` один раз (`GET /story-gifts/access`) и раздаёт через `StoryAccessContext`; вкладка видна при любом виде, кроме `closed`; неизвестный режим/мусор = закрыто.
- Р-ST3-FE-3: правила — два флажка (18+ и «принимаю правила»), тело `{termsVersion, adult:true}` только при обоих.
- Р-ST3-FE-4: `charge` читается с верхнего уровня сметы/карточки (запасной путь `estimate.charge`); у владельца (`credits:0`, не `free`) диалога цены нет. Видеосборка получила подтверждение `StoryConfirm` с ценой; Nova — цена дописана в существующий диалог.
- Р-ST3-FE-5: 402 — числа из `error.details.required/balance` (BE кладёт их в `upstreamDetails`), запасной баланс — из `/me/plan`; кнопка «Купить кредиты» → `#/credits`.
- Р-ST3-FE-6: ссылка видна только сразу после выдачи (хранится хеш). Если карточка говорит, что ссылка активна, — срок и «Снять с публикации» плюс подсказка «чтобы получить новую, снимите текущую» (BE отвечает 409 на вторую ссылку). Если состояние неизвестно, «Снять» показывается всегда (DELETE идемпотентен).
- Р-ST3-FE-7: `retention.basis === 'published'` → текст «ссылка закроется <дата>», а не «будет удалено».
- Р-ST3-FE-8: тексты валидатора (3 `STORY_PROMISE_*` + 3 `STORY_HINT_*`) — на языке интерфейса по коду; неизвестный код — текст сервера как есть.
- Р-ST3-FE-9: диплинк уже есть: `startapp=e_stories` → `#/stories` (проверен в Telegram 16.10); bare `startapp=stories` строгий парсер не принимает — лендинг собирает `e_stories`.
- Р-ST3-FE-10 (доработка): обязательный флажок согласия рассказчика — общим механизмом `StoryConfirmText.requiredCheck` (StoryConfirm), в `ConfirmDialog` добавлен `confirmDisabled`, а флажки включены в Tab-цикл диалога (иначе флажок недостижим с клавиатуры). Поле `narratorPublicConsent: true` уходит только при `narratorPublicConsentRequired`; на 400 `STORY_NARRATOR_PUBLIC_CONSENT_REQUIRED` показывается понятный текст и карточка перечитывается.
- Р-ST3-FE-11: `legal-markdown.test.ts` — только типизация (`assert.match` → `assert.ok(re.test)`, явное сужение `story`), смысл проверок не менялся.
- Р-ST3-FE-12 (аудит U): весь UI Story — секция словаря `storyUi` (ru/uk/en; de/es = en по решению главного агента), заменяет Р-ST3-FE-1. Чистые помощники (`story-confirm`, `story-wizard`, `story-video-plan`, `story-errors`) принимают строки параметром, по умолчанию — ru из словаря (старые тесты без изменений). Вне ru русский текст сервера не показывается: коды → словарь, иначе текст по статусу; препятствия сметы видео — по известным фразам, иначе общий текст.
- Р-ST3-FE-13: не-владелец (role≠owner) не видит разбор референсов, реестр редакций, образ рассказчика, бюджет/резерв/смету провайдера; бюджет-потолок для него — $5 скрыто; цена — только кредиты (≈$).
- Р-ST3-FE-14: `expectedCredits` — всегда из показанной сметы (`charge?.credits ?? 0`); 409 `STORY_PRICE_CHANGED` → перечитать карточку/смету, взять `details.charge`, открыть подтверждение заново.
- Р-ST3-FE-15: `readOnly`/`pilot_revoked` → вид `readonly`: баннер, список, карточки, скачивание, удаление, срок; без мастера, сборок, QA, одобрения, новой ссылки (снять с публикации — можно).
- Р-ST3-FE-16: язык сказки по умолчанию = язык интерфейса, если в каталоге есть сказки на нём, иначе первый язык каталога.
- Для BE: согласия `voiceConsentText`/`recordingConsentText` и `rights` каталога приходят по-русски — нужна локализация на стороне сервера (FE не переводит юридически версионированный текст).
- Р-ST3-FE-17: запросы Story (`/story-gifts…`, `/story-gift/…`, `/public/story-…`, включая fetch субтитров) несут Accept-Language = язык интерфейса (de/es → en) — правка в перехватчике `services/api.ts`, остальные запросы без изменений; смена языка перечитывает каталог и видеопанель.
- Р-ST3-FE-18 (ST3-U-15): просьба о согласии рассказчика при действующей ссылке и подпись видео — по `narratorPublicConsentPending`; `narratorPublicConsentRequired` — только флажок при первой выдаче ссылки; после сохранения согласия кнопка скрывается сразу (и после перечитывания карточки).
