# QA «Стенды»: шаблонный MVP — 14.10.2026

Клиентский экран `#/sites/:siteId/qa-stands` добавлен рядом с кейсами и прогонами. Описание → показ контракта → подтверждение → сохранённый стенд. Фиксированный шаблон records: демо-роли, список/поиск, формы, создание/удаление, ошибки, сброс, экспорт JSON и самостоятельная проверка engine. Требования вне шаблона явно не выдаются за выполненные.

Сервер хранит контракт и синтетические записи в новой `qa_stands`. Каждый запрос проверяет QA-права и принадлежность сайта аккаунту. Составной FK не даёт связать стенд с чужим сайтом. Создание идемпотентно по requestId; запись использует revision compare-and-swap. Демо-роль не заменяет авторизацию кабинета. PUBLIC и assist_public не имеют доступа к таблице.

REST GET/POST `/qa/sites/:siteId/stands/:id/mock/records`, DELETE `…/records/:recordId` возвращают настоящие HTTP-статусы. POST `…/:id/mock` — интерактивный envelope со смоделированным статусом. Нет публичных адресов/внешних credentials/исполнения кода. Все поля обязательны, максимум 8 × 500 символов; максимум 100 записей. Доступно удаление стенда.

## Проверки

- Локальные Jest: 33 проверки прошли (контракт, account/site scope, права, идемпотентность, параллельные изменения, HTTP-коды, tenant registry).
- Три проверки настоящего Postgres добавлены в существующий backend CI; локально пропущены, поскольку изолированная CI-БД не запущена.
- Браузер Chromium, viewport 390×844: создание контракта/стенда, отказ viewer, submit editor, отображение записи, контрактная проверка и reset прошли. Хранилище этого UI-прогона имитировалось; это не production-приёмка.
- TypeScript backend и кабинет, сборка кабинета, router test, проверки формата/линтера. Полный production-путь подтверждается отдельно после миграции и deployment.

## Границы релиза

Это шаблонный пилот, а не произвольная генерация сайта LLM. «Вход» — выбор тестовой роли, а не проверка пароля. Нет голоса, отдельного preview URL, OpenAPI, PATCH, latency/replay, истории аудита, интеграций Tutorial/AI helper и глобального dashboard. Семь встроенных проверок engine работают на изолированных данных и не проверяют браузерную вёрстку.

Для запуска нужны штатная миграция `20261022090000_qa_stands` и deployment sites-backend/assist. Нельзя считать production готовым по одному зелёному frontend build. Следующие этапы зафиксированы в TODO и §15 ТЗ.
