# Съёмка настоящих кадров для страницы поздравлений

Порядок работы для этапа I ТЗ
`docs-tz/TZ-Greeting-2.0-Adaptive-Persona-Landing.md` (§5.3 «Волна 2 —
настоящие кадры»). Близнец `doc/TUTORIAL-FRAMES-CAPTURE.md`: тот же
конвейер (`ui-snapshot` → `scripts/tutorial-frames-process.mjs` →
список локалей → шов в `check-docs`), здесь — только то, чем
поздравления отличаются.

Нужен доступ оператора в админку и работающий стенд (staging или прод):
headless-браузер и фикстурные данные живут там, из песочницы их нет.

## Что на каком кадре

| Кадр | Сюжет (§5.2 п.3) | Маршрут | Секция в кадре |
|---|---|---|---|
| 1 | повод и бриф | `greeting-video` | `greeting-brief-card` |
| 2 | «Характер ролика» | `greeting-video-ready` | `greeting-character-block` |
| 3 | сценарий | `greeting-video-ready` | `greeting-script-card` |
| 4 | готовый ролик | `greeting-video-done` | `greeting-video-card` |

Таблица — для чтения; источник правды — `GREETING_FRAME_SHOTS` в
`backend/src/modules/ui-snapshot/greeting-frames-capture.service.ts`, и
его держат тесты (порядок, число кадров против `GREETING_FRAME_COUNT`
лендинга, существование каждого `data-qa` в мастере).

Шагов у съёмки нет: все четыре состояния лежат в базе — это разные
фикстурные проекты, и состояние задаёт адрес. Мастер — одна лента из
девяти карточек, поэтому каждый кадр прокручивается к своей секции
(`scrollTo`) и начинается сразу под шапкой приложения.

## Имена в кадре — размыты, и это не упущение

Поля с именами и свободным текстом помечены
`data-qa-mask="personal-…"`: получатель, отправитель, личное пожелание,
особый повод, текст сценария, титры и подсказки титров, подписи и
описания референсов, сводка «Характера ролика», подпись своего голоса,
строки «кому / повод» в карточке голосового согласия. Прогон размывает
их в ЛЮБОМ режиме, в том числе немаскированном
(`PERSONAL_TEXT_MASK_CSS` в `ui-snapshot-runner.service.ts`): выдуманное
имя на маркетинговом кадре запрещено (§5.5 образца), а без имён кадр
брифа не снять. Рамка поля остаётся видна — пропадают только буквы.
Подсказка-плейсхолдер у помеченного поля тоже скрыта, и это намеренно:
у титров она собрана из брифа и несёт имя получателя.

Список полей держит `frontend/scripts/greeting-steps.test.ts` (блок
«Маски личного текста»): новое поле с именем без маски его уронит.

Сам ролик в кадре 4 НЕ размывается — он и есть то, что кадр показывает.
Поэтому у проекта под кадр 4 в брифе нет имени человека вовсе:
«Коллеги» от «Команды», повод «Новый год» (`fixture-seed.ts`).

## 0. Что должно быть настроено

Всё из `doc/TUTORIAL-FRAMES-CAPTURE.md` §0 (`FIXTURE_TELEGRAM_ID`,
`FIXTURE_USER_TOKEN`, `TMA_PUBLIC_URL`, `API_PUBLIC_URL`,
`RESEMBLE_VOICE_ID`) плюс `GROK_API_KEY` — ведущего ролика рисует Grok.
На стенде должен быть выкачен код этого этапа — и бэкенд, и фронтенд
(маски живут во фронтенде: старый фронтенд отдаст кадр с именами).

## 1. Завести фикстуру

```
POST /api/admin/tutorial-runner/seed-fixture-user
```

Идемпотентно. С этим этапом заводит ЧЕТВЁРТЫЙ проект-поздравление —
`fixture-tutorial-greeting-done-project` («кадр „готовый ролик“») — с
сессией без сценария. Его сессию пересев не перезаписывает: в ней будет
оплаченный ролик, и «Завести фикстуру» не должно его стирать.

## 2. Отрендерить ролик фикстуры (платно, один раз)

```
POST /api/admin/ui-snapshot/greeting-frames/fixture-video
```

Каждый вызов делает один шаг и отвечает `stage`:

- первый вызов — сценарий настоящим конвейером (не текстом из сида) и
  запуск рендера → `started`. **Это платно**: сценарий и ролик Grok;
- дальше повторять раз в 20–30 секунд → `rendering`, затем
  `post-processing`, пока не станет `complete`. Повтор не платит второй
  раз: идущий рендер только опрашивается, готовый отдаётся как есть;
- `failed` — провайдер отказал; следующий вызов запустит рендер заново
  (и снова платно);
- `post-processing` — картинка готова, но своя озвучка ещё кладётся
  постобработкой: **слушать рано**, повторять вызов (бесплатно — это
  опрос, не рендер; `rerender` на этой стадии не срабатывает);
- `complete` — готово вместе с постобработкой. Если в ответе есть
  `postError` — постобработка упала, ролик без своего голоса: скорее
  всего, его придётся переснять.

Сессию ролика крон уборки удаляет, если рендер не начат за срок жизни
сессии (готовые ролики он не трогает). Тогда вызов ответит `skipped` —
повторите шаг 1 (пересев заводит сессию заново) и продолжайте.

Готовый ролик — в `video.downloadUrl`; слушать его — **только после
`stage: "complete"`**. **Посмотрите его целиком**:
ИИ-ведущий, ни одного имени человека, ни чужого бренда, голос звучит.
Не годится — `{ "rerender": true }` в теле того же вызова снимет его
заново тем же сценарием (платно; только строгим `true`). Готовый ролик
на месте не перерендеривается (сервер отвечает 409
`GREETING_VIDEO_ALREADY_READY`), поэтому вызов заводит **новую версию
сессии** проекта с копией брифа, фото и сценария и рендерит её; прежний
ролик остаётся в старой сессии. `sessionId` в ответе — уже новой версии,
и следующие вызовы (опрос) находят её сами: берётся последняя сессия
проекта. Если фото не скопировалось, сценарий в новой версии
собирается заново тем же конвейером.

Ролик пользователей этот вызов не касается: он работает только с
проектом `FIXTURE_IDS.greetingDoneProject` фикстурного пользователя.

## 3. Снять кадры

```
POST /api/admin/ui-snapshot/greeting-frames
{ "locales": ["ru"], "theme": "dark" }
```

Одна локаль за вызов — надёжнее: на кадр поднимается свой браузер,
четыре кадра × пять локалей в один запрос могут не уложиться в предел
времени функции. Ответ — та же форма, что у `tutorial-frames`:

```json
{ "locales": [
  { "locale": "ru",
    "cards": { "1": "https://blob/…", "2": "…", "3": "…", "4": "…" },
    "problems": [] } ] }
```

`problems` непустой — часть кадров не снята, годные всё равно отданы.
Пустой кадр 4 с подсказкой про `fixture-video` — у фикстуры ещё нет
готового ролика (шаг 2 не пройден или ролик ещё рендерится).
Снимать кадр 4 — только после `stage: "complete"` на шаге 2: маршрут
«готовый ролик» открывается уже на `post-processing`, и в плеере тогда
окажется ролик без своей озвучки.

Вручную один кадр — `POST /api/admin/ui-snapshot/run` с
`"unmasked": true`, `"deviceScaleFactor": 2`, ровно одним маршрутом в
`routeKeys` и `"scrollTo": "[data-qa=\"greeting-script-card\"]"`.

## 4. Проверить каждый кадр ПЕРЕД обработкой

- [ ] ни одного читаемого имени, пожелания, текста сценария или титра
      — на их месте размытые строки; если буквы читаются — на стенде
      старый фронтенд, кадр в брак;
- [ ] в кадре ровно своя секция (бриф / «Характер ролика» / сценарий /
      ролик), заголовок секции не спрятан под шапкой;
- [ ] кадр 4: в плеере — кадр ролика с ведущим, а не чёрный
      прямоугольник; жёлтой строки «голос не выбран» нет;
- [ ] интерфейс на языке прогона, тёмная тема;
- [ ] экран в рабочем состоянии: не спиннер, не ошибка, нет плашек
      лимита и советника.

## 5. Обработать и положить

Скачайте четыре PNG по адресам из `cards` и:

```
node scripts/tutorial-frames-process.mjs --greeting ru кадр1.png кадр2.png кадр3.png кадр4.png
```

Обрежет верхние 85%, приведёт к 780×1434, подберёт качество под бюджет
120 КБ и положит `landing/public/illustrations/greet-shot-ru-{1..4}.avif`.
Не влезло — скрипт падает (см. образец §4).

## 6. Включить локаль — последним шагом

Дописать её в `GREETING_REAL_FRAME_LOCALES`
(`landing/src/lib/greeting-frames.ts`). Вместе с этим сами меняются
картинки и оговорка «это схемы». Порядок обязателен: список раньше
файлов — страница отдаст 404; файлы без списка — мёртвый груз. Обе
ошибки ловит шов 17-бис в `scripts/check-docs.mjs`.

## 7. Проверить

```
cd landing && npm run build && npm run lint && npm run test
node scripts/check-docs.mjs
```

## Чего этот порядок не покрывает

- **Пересъёмку при смене мастера.** Кадры статичны; перерисованный
  мастер делает их устаревшими молча — пункт ручного чек-листа релиза.
- **Годность кадра.** Прогон снимает то, что просили; отбор §4 — только
  глазами.
- **Один ролик на пять локалей.** Ролик фикстуры один, его
  язык — язык сценария; на кадре видна картинка, а не звук, поэтому
  интерфейс вокруг ролика локализуется, а сам ролик — нет.
