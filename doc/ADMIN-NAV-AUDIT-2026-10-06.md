# Аудит навигации админки — 06.10.2026

Проверены AdminNav, layout, root/login переходы, маршруты и CSS.
Операторский вход недоступен: выводы по коду, реальный экран после входа
нужно проверить отдельно. Изменения меню этим аудитом не внесены.

## Что мешает оператору

- **Высокий приоритет: нет входной очереди внимания.** Root и оба успешных
  перехода login ведут в `/sessions`. Сессии — одна рабочая область,
  поэтому ошибки крона, модерация и демо на одобрение не видны при входе.
- **Высокий приоритет: «Система» стала сборным разделом.** 12 из 30 ссылок
  находятся там: диагностика, воронка, приглашения, три разных помощника,
  обучение и настройки. По названию невозможно предсказать расположение
  воронки или сценариев обучалки. Старый комментарий говорит о 16 ссылках;
  модель навигации не пересматривалась вместе с ростом приложения.
- **Средний приоритет: группы описывают разные основания.** «Контент»
  смешивает маркетплейс, модерацию, библиотеку и блог; «Коммерция» —
  пользователей, рассылку и расходы. Нет одного принципа поиска функции.
- **Средний приоритет: рабочие очереди спрятаны среди справочников.**
  Модерация, публикации и ошибки требуют решений, настройки/аналитика —
  просмотра. Сейчас приоритет и число ожидающих действий не показаны.
- **Средний приоритет: выпадающий список не ограничен viewport.**
  `.admin-nav-dropdown` абсолютный, без max-height/scroll; 12 строк по
  ≥40px плюс отступы. `white-space: nowrap` и min-width 200px без
  ограничения ширины могут выводить длинные подписи за край телефона.
  Это риск из кода, а не измеренное переполнение реальной сессии.
- **Средний приоритет: неполное поведение с клавиатурой.** Escape закрывает
  группу, но не возвращает фокус на триггер, если фокус был внутри неё;
  нет aria-controls. Обычные Tab/Enter доступны, однако aria-haspopup
  обещает popup без определённого menu-паттерна. Для навигации использовать
  disclosure с обычными ссылками, не изображать application menu.
- **Низкий приоритет: нечёткие названия.** «Помощник (клиентские сайты)» и
  «Обучалки по сайтам» трудно различить без опыта. Нужны подписи по объекту
  и задаче: настройки помощника / заказы обучающих видео. «Оплата» точнее
  обозначить как «Платежи», «Кроны» — «Запуски по расписанию».

Все 30 верхнеуровневых рабочих страниц представлены, дубли ссылок не
найдены. `/sessions/[id]` — вложенный экран, `/login` — вход, root —
redirect; отсутствие отдельных пунктов для них нормально.

## Предлагаемая структура

При таком количестве страниц рекомендована боковая навигация с группами,
активным пунктом и запоминанием раскрытия. На телефоне — выдвижная панель
с собственной прокруткой и возвратом фокуса. «Обзор» первым и отдельно.
Все существующие адреса сохраняются. Группировка по задачам:

- **Работа с пользователями:** `/sessions` Сессии;
  `/users` Пользователи.
- **Модерация и маркетплейс:** `/publications` Публикации на модерации;
  `/shared-videos` Публичные страницы видео;
  `/creator-profiles` Исполнители; `/portfolio-items` Портфолио;
  `/auctions` Аукционы. Внутри сначала очереди решений, затем справочники.
- **Создание видео:** `/library` Библиотека референсов;
  `/catalog-batches` Пакетная генерация; `/ab-tests` A/B-варианты;
  `/feed-imports` Импорт фида; `/virtual-studio` Виртуальная студия;
  `/actors` AI-аватары (пилот).
- **Обучающие материалы:** `/tutorial-scenarios` Сценарии демо;
  `/site-tutorial-drafts` Обучающие видео по сайтам; `/blog` Блог.
  Проверки качества демо открываются из сценария и дашборда; новый
  отдельный пункт добавлять только если нужна самостоятельная очередь.
- **Продвижение:** `/marketing` Рассылки; `/funnel` Воронка;
  `/referrals` Приглашения.
- **Финансы:** `/payments` Платежи; `/balances` Балансы;
  `/costs` Расходы.
- **ИИ-помощники:** `/assistant` Консультант лендинга;
  `/wizard-guide` Советник мастера; `/assist-platform` Помощник сайтов.
- **Эксплуатация:** `/cron` Запуски по расписанию;
  `/ui-snapshots` Снимки интерфейса; `/testing` Тестирование;
  `/telemetry` Телеметрия; `/settings` Настройки.

В группах 2–6 пунктов вместо одного списка на 12. Не дублировать страницу
в нескольких группах; дашборд может ссылаться на неё из карточки проблемы.
Иконка/счётчик показывают действие, требующее внимания, только по реальным
данным. Недоступный источник не показывать как ноль. Поиск по названиям
можно добавить позже; он не заменяет понятную структуру.

## Порядок внедрения и приёмка

1. Единый каталог маршрутов/подписей/групп, отделённый от компонента.
   Проверка уникальности ссылок и покрытия существующих рабочих маршрутов.
2. Обзор и защищённая очередь внимания по
   `TUTORIAL-DEMO-QUALITY-SPEC.md`. Обновить root и оба успешных login
   перехода; корректно выделять root только при точном совпадении, иначе
   `startsWith('/')` отметит его активным на каждом экране.
3. Боковая панель, адаптация ширины контента, мобильное закрытие, Escape,
   восстановление фокуса, доступные названия и aria-current для вложенных
   маршрутов. Не менять проверку прав и существующие действия страниц.
4. Проверить desktop и мобильные 320/390px, длинные подписи, весь список,
   Tab/Shift+Tab/Enter/Escape, вложенную сессию, reload и вход/выход.
5. **Операторский TODO:** после восстановления входа подтвердить названия
   и частоту задач; пройти реальный маршрут «увидел проблему → открыл
   объект → решил → вернулся в обзор». Авторизация не блокирует работу
   над каталогом маршрутов, UI и backend очередью.
