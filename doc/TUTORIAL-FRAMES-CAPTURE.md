## 0. Что должно быть настроено

- `FIXTURE_TELEGRAM_ID`, `FIXTURE_USER_TOKEN`, `TMA_PUBLIC_URL` в
  окружении бэкенда (вкладка «Настройки», группа «Обучалка»).
- Доступ оператора: все вызовы ниже идут под `AdminSessionGuard` и
  `assertOperator`.

## 1. Завести фикстуру

```
POST /api/admin/tutorial-runner/seed-fixture-user
```

Идемпотентно. Заводит в том числе **проект третьего типа**
(`CLIENT_SITE`) — без него маршрут `site-tutorial` не резолвится.
Черновика обучалки фикстура НЕ создаёт сознательно: кадры в нём должны
быть настоящими, а выдуманные дали бы экран с битыми картинками.

## 2. Довести мастер до нужных состояний — вручную, по одному разу

Кадров четыре, а стадий у мастера три (`url` → `page` → `review`), и
соответствие **не один к одному**:

| Карточка | Что на ней | Стадия | Как получить |
|---|---|---|---|
| 1 | «Вставили ссылку» | `url` | открыть мастер фикстурного проекта, вставить адрес нашего сайта, НЕ нажимать |
| 2 | «Увидели настоящий экран» | `page` | нажать — пришёл кадр и список найденных полей; ничего не заполнять |
| 3 | «Заполнили и нажали» | `page` | заполнить поле, навести на кнопку; снимать ДО перехода |
| 4 | «Получили ролик» | `review` + `postprod-video` | пройти сценарий до «Готово», дождаться сборки |

Карточки 2 и 3 — **два момента одной стадии**. Одного прогона мало:
либо две остановки руками, либо сценарий с паузой.

**И этот шаг делает только владелец, не ассистент.** Вход фикстуры —
заголовок `X-Fixture-Token` со значением `FIXTURE_USER_TOKEN`; это
секрет, и подставлять его в браузер за владельца ассистент не станет.
Прогон снимков ходит под ним изнутри сервера, поэтому карточка 1 (и
карточка 4, когда у фикстуры есть готовый ролик) снимается кнопкой
целиком без человека, а 2 и 3 — нет: между ними надо руками довести
мастер до нужного состояния. Решение владельца от 26.09.2026: делать
только то, что снимается без него; значит секция остаётся на схемах,
пока он не пройдёт мастер сам.

**Какой сайт открываем:** `viral4creators.app` (решение владельца, §9
ТЗ). Не сайт заказчика — чужой показывать не вправе; не сам
`tutorial.*` — снимок страницы внутри неё самой мешает понять, что где.

## 3. Снять

По прогону на локаль:

```
POST /api/admin/ui-snapshot/run
{ "routeKeys": ["site-tutorial"], "locale": "ru", "theme": "dark",
  "unmasked": true, "deviceScaleFactor": 2 }
```

и отдельно для четвёртой карточки — `"routeKeys": ["postprod-video"]`.

- `unmasked: true` обязателен: без него кадр сайта скрыт маской —
  она правильна для крона регрессий и вредна здесь.
- `deviceScaleFactor: 2` обязателен, и это находка прода. Вьюпорт
  прогона — 390×844 **CSS**-пикселей; при плотности 1 файл выходит
  ровно 390×844 растровых, а странице нужен кадр шириной 780.
  Растянуть 390 до 780 постобработкой нельзя — это не резкость, а её
  имитация, и `tutorial-frames-process.mjs` такой вход отклоняет с
  объяснением. Плотность разрешена **только вместе с `unmasked`**:
  размер кадра входит в отпечаток, и маскированный прогон плотностью 2
  записал бы в базу строку, не сравнимую ни с одной прежней, — крон на
  следующем тике честно закричал бы «изменилось». Сочетание
  отвергается с 400, а не исправляется молча.
- Такой прогон **не пишет строк `UiSnapshot`, не сравнивается и не шлёт
  тревог**: иначе подменил бы базовый отпечаток и следующий тик крона
  закричал бы на собственную картинку.
- Адреса файлов — в `outcomes[].blobUrl`. Если `outcomes` короче
  запрошенного, смотрите `deferred`: кончился бюджет времени.

## 4. Проверить каждый кадр ПЕРЕД обработкой

Отбраковывать, не жалея: переснять дешевле, чем объяснять.

- [ ] в кадре нет имени фикстурного пользователя, аватара, баланса,
      меток времени (маска на имени стоит, но проверьте глазами);
- [ ] в окне сайта — наш собственный сайт, ни одного чужого домена,
      логотипа или клиентских данных;
- [ ] интерфейс на языке прогона (`locale` действительно применился, а
      не только записался — с этапа H он выставляется через
      `v4c_locale`/`v4c_theme`);
- [ ] тёмная тема;
- [ ] экран в рабочем состоянии, а не в ошибке, спиннере или пустоте.

## 5. Обработать и положить

```
node scripts/tutorial-frames-process.mjs ru кадр1.png кадр2.png кадр3.png кадр4.png
```

Обрежет верхние **85%**, приведёт к **780×1434**, подберёт качество под
бюджет 120 КБ и положит в `landing/public/illustrations/`. Не влезло
даже на пределе — скрипт падает: замыленный снимок на странице, которая
продаёт достоверность, хуже отсутствующего.

**Почему 85, а не 60.** В первой редакции стояло 60% — число взято из
головы, до того как появился хоть один настоящий кадр. На кадре с прода
главная кнопка стадии `url` («Исследовать») стоит на **y ≈ 666 из
844** — то есть обрезка по 60% (506px) отрезала бы ровно то, ради чего
карточка и существует: действие. Подвал начинается около 775, так что
85% (717px) берут весь рабочий экран и не берут навигацию. Если мастер
перерисуют и кнопка уедет — это число надо перемерить, а не доверять
ему.

## 6. Включить локаль — последним шагом

Дописать её в `REAL_FRAME_LOCALES`
(`landing/src/lib/tutorial-frames.ts`). Тогда же и только тогда
меняются: картинки, `alt` у них и оговорка под заголовком
(`how.lead` → `how.leadReal`). Развести их руками негде — это и есть
смысл того модуля.

Порядок обязателен: объявить локаль раньше файлов — страница пообещает
настоящие кадры и отдаст 404. Обе ошибки ловит шов 17 в
`scripts/check-docs.mjs`, обе проверены мутацией.

## 7. Проверить

```
cd landing && npm run build && npm run lint && npm run test
node scripts/check-docs.mjs
```

Плюс замер LCP. **База, снятая 26.09.2026** на профиле «медленный 4G»
(150 мс задержки, 1,6 Мбит/с, CPU ×4), медиана трёх прогонов:

| Ширина | LCP | Элемент |
|---|---|---|
| 390 | **608 мс** | `<p>` подзаголовка |
| 1280 | **644 мс** | `<h1>` |

Важное из этого замера: **LCP-элемент сейчас текстовый, а не
картинка.** Кадр в первом экране — SVG на 7 КБ, и опасение §9 ТЗ про
LCP пока не сбылось. На этапе I там окажется растровый снимок; если
после замены LCP-элементом станет `<img>` и время вырастет — это и есть
сигнал снимать картинку из hero (критерий 8.1.7). Остальной hero —
сетка и плитки — остаётся в любом случае.

## Чего этот порядок не покрывает

- **Пересъёмку при смене интерфейса.** Кадры статичны: мастер
  перерисуют — они устареют молча. Шов на это завести нечем (сравнивать
  картинку не с чем), так что это пункт ручного чек-листа релиза.
- **Локали сверх снятых.** Пока локали нет в списке, она показывает
  схемы, и это корректное состояние, а не поломка: переключение
  поштучное.
- **Стадию `page` двумя моментами.** Автоматизировать можно сценарием с
  паузой, но сценарий придётся написать; сегодня это руки.
