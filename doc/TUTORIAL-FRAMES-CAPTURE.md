# Съёмка настоящих кадров для секции «Как это выглядит»

Порядок работы для этапа I ТЗ
`docs-tz/TZ-Enterprise-Tutorial-Landing.md`. Нужен доступ оператора в
админку и работающий прод: headless-браузер и фикстурные данные живут
там, из песочницы их нет.

Всё, что можно было сделать без прода, сделано заранее — разметка,
стили, переключатель, скрипт обработки и проверки. Здесь остаётся
только сам прогон и отбор.

Кадры страницы поздравлений снимаются тем же конвейером, но своим
порядком (фикстурный ролик, прокрутка к секции, размытые имена) —
`doc/GREETING-FRAMES-CAPTURE.md`.

## Состояние на 27.09.2026 — тупика нет, был неверный инструмент

Редакция от 26.09.2026 заканчивалась выводом «человек нужен для всех
четырёх карточек». Вывод неверен, и вот почему.

Он опирался на наблюдение: прогон `POST /admin/ui-snapshot/run`
открывает маршрут и снимает то, что там есть, — а карточка 1 обещает
«вставили ссылку», и на свежем экране поле пустое. Наблюдение верное.
Неверен шаг дальше: из него заключили, что состояние недостижимо, хотя
недостижимо оно **только открытием маршрута**.

Текст в поле до отправки живёт в React и в базу не попадает. Значит
снять его можно ровно одним способом — **действовать на уже открытом
экране и снимать между действиями**. Механика для этого в проекте была
всё это время: `scenario-runner.ts`, из кадров которого собираются
обучающие ролики, умеет `fill`/`click`/`waitFor` и снимает кадр **после
каждого успешного шага**. Ему не хватало только правильного вьюпорта
(он вовсе не задаёт его — puppeteer по умолчанию 800×600 @1x), а
снимающему прогону не хватало шагов.

> **28.09.2026, этап H ТЗ `docs-tz/TZ-Tutorial-Video-Voiced.md`.**
> Вьюпорт тогда поправили только снимающему прогону. Ночная обучалка
> оставалась на 800×600 до этапа H: её кадры ложились полосой посреди
> портретного холста ролика. Теперь оба пути берут один
> `SCENARIO_VIEWPORT` (390×844) из `scenario-runner.ts`, ночная
> обучалка — с плотностью 2.

Правка 27.09.2026 соединила два куска: операторский прогон
`ui-snapshot` принимает необязательные `steps` и отдаёт кадр после
каждого. Вьюпорт, плотность, локаль, тема и немаскированная съёмка у
него уже были.

### Что это меняет по карточкам

| Карточка | Где живёт состояние | Как снимается |
|---|---|---|
| 1 «вставили ссылку» | только React | кадр после `fill #site-url` |
| 2 «увидели экран» | черновик в базе | кадр после `waitFor` кадра страницы |
| 3 «заполнили и нажали» | только React | кадр после `fill #f-0` |
| 4 «получили ролик» | ролик в базе | отдельный прогон по `postprod-video` |

Рук человека не нужно ни на одной. Остаётся его решение — какие
локали и годится ли кадр (§4).

## 1. Завести фикстуру

```
POST /api/admin/tutorial-runner/seed-fixture-user
```

Идемпотентно. Заводит в том числе **проект третьего типа**
(`CLIENT_SITE`) — без него маршрут `site-tutorial` не резолвится.
Черновика обучалки фикстура НЕ создаёт сознательно: кадры в нём должны
быть настоящими, а выдуманные дали бы экран с битыми картинками.

## 2. Снять все четыре карточки — один вызов

```
POST /api/admin/ui-snapshot/tutorial-frames
{ "locales": ["ru", "en"], "theme": "dark" }
```

Всё остальное сервер делает сам, по локали за раз:

1. сбрасывает черновик обучалки (иначе вторая локаль снимет вместо
   пустой формы стадию `page` — карточка 1 выйдет не той, и молча);
2. прогоняет мастер со съёмочным сценарием и снимает кадр после
   каждого шага;
3. отдельным прогоном снимает экран готового ролика;
4. раскладывает кадры по карточкам.

Ответ:

```json
{ "locales": [
  { "locale": "ru",
    "cards": { "1": "https://blob/…", "2": "…", "3": "…", "4": "…" },
    "problems": [] } ] }
```

`problems` непустой — часть кадров не снята; годные всё равно отданы.
Номера недостающих карточек называет последняя запись («не сняты
карточки: …»), остальные записи — свободный текст про мастер, ролик
или черновик. Прогон не бросает исключение ради одной неудачной
локали.

Отдельно от `locales` есть поле верхнего уровня **`skipped`**: съёмка
не начиналась вовсе (не настроен фикстурный вход, у фикстуры нет
проекта «сайт заказчика»). В этом случае `locales` пуст, и причину
надо смотреть там, а не в `problems`.

Что проверяет сам прогон, а что остаётся глазам: первым шагом
сценария стоит `assertVisible` на поле ссылки — он падает, если экран
не дошёл до нужной стадии, висит спиннером или отдал ошибку (§4
«экран в рабочем состоянии»). Локаль, содержимое ролика и общий вид
машина не проверяет.

**Что где живёт.** Соответствие «кадр после какого ШАГА → какая
карточка» раньше было таблицей в этом документе, то есть знанием в
голове у того, кто документ недавно читал. Теперь оно в
`tutorial-frames-capture.service.ts` (`CARD_BY_STEP_INDEX`) и покрыто
тестами: из пяти шаговых кадров на страницу идут три — кадр после
первого шага (проверка «экран рабочий») и после третьего (сразу
после клика, страница ещё грузится) не иллюстрируют ни одну подпись.
Проверяется мутацией; когда съёмочный сценарий вырос на шаг, тесты
этот сдвиг и поймали.

Ключ — именно номер ШАГА, а не позиция в списке снятых кадров
(правка аудита этапа A ТЗ `docs-tz/TZ-Tutorial-Video-Voiced.md`).
Скриншот снимается best-effort: единичный сбой глотается, чтобы не
ронять прогон, — и поиск по позиции тогда молча подставил бы в
карточку экран соседнего шага. Внешне всё снято, замечает только
глаз на лендинге. В имени файла в хранилище номер шага 1-based
(«третий шаг» читается человеком), в поле `shots[].stepIndex`
прогона — 0-based; разница на единицу возникает в одном месте, там,
где снимок заливается.

`siteUrl` по умолчанию `https://viral4creators.app` — свой сайт, §9 ТЗ.
Переопределять его можно, но только на https-адрес; чужой сайт в кадре
показывать не вправе.

### Если нужно вручную

Низкоуровневый прогон никуда не делся — `POST /api/admin/ui-snapshot/run`
со своими `steps`. Ограничения: `unmasked: true` обязателен (шаги
МЕНЯЮТ состояние продукта, а сравниваемый прогон обязан быть
наблюдателем), ровно один маршрут в `routeKeys` (шаги пишутся под
конкретный экран), `goto` и `triggerPaidOperation` запрещены. Один шаг
— до 45 с: клик «Исследовать» поднимает на сервере отдельный браузер.

Селекторы сценария — собственные якоря продукта `#site-url` и `#f-0`
плюс `data-qa="client-site-explore"` у кнопки. По тексту искать нельзя:
кадры снимаются в нескольких локалях.

## 3. Проверить каждый кадр ПЕРЕД обработкой

Отбраковывать, не жалея: переснять дешевле, чем объяснять.

- [ ] в кадре нет имени фикстурного пользователя, аватара, баланса,
      меток времени. **Маски здесь НЕТ**, и это не упущение: съёмка
      идёт с `unmasked: true`, иначе скрытым окажется кадр сайта —
      главное, ради чего карточка и нужна. Прежняя редакция обещала
      «маска на имени стоит» — неправда для этого режима, и находка
      аудита 27.09.2026 именно в том, что обещание касалось личных
      данных;
- [ ] в окне сайта — наш собственный сайт, ни одного чужого домена,
      логотипа или клиентских данных;
- [ ] интерфейс на языке прогона (`locale` действительно применился, а
      не только записался — с этапа H он выставляется через
      `v4c_locale`/`v4c_theme`);
- [ ] тёмная тема;
- [ ] экран в рабочем состоянии, а не в ошибке, спиннере или пустоте.

## 4. Обработать и положить

```
node scripts/tutorial-frames-process.mjs ru кадр1.png кадр2.png кадр3.png кадр4.png
```

Обрежет верхние **85%**, приведёт к **780×1434**, подберёт качество под
бюджет 120 КБ и положит в `landing/public/illustrations/`. Не влезло
даже на пределе — скрипт падает: замыленный снимок на странице, которая
продаёт достоверность, хуже отсутствующего.

**Почему 85, а не 60.** В первой редакции стояло 60% — число взято из
головы, до того как появился хоть один настоящий кадр. На кадре с прода
главная кнопка стадии `url` («Исследовать») стоит на **y ≈ 666 из
844** — то есть обрезка по 60% (506px) отрезала бы ровно то, ради чего
карточка и существует: действие. Подвал начинается около 775, так что
85% (717px) берут весь рабочий экран и не берут навигацию. Если мастер
перерисуют и кнопка уедет — это число надо перемерить, а не доверять
ему.

## 5. Включить локаль — последним шагом

Дописать её в `REAL_FRAME_LOCALES`
(`landing/src/lib/tutorial-frames.ts`). Тогда же и только тогда
меняются: картинки, `alt` у них и оговорка под заголовком
(`how.lead` → `how.leadReal`). Развести их руками негде — это и есть
смысл того модуля.

Порядок обязателен: объявить локаль раньше файлов — страница пообещает
настоящие кадры и отдаст 404. Обе ошибки ловит шов 17 в
`scripts/check-docs.mjs`, обе проверены мутацией.

## Где автоматика заканчивается — и почему это не недоделка

Съёмка автоматическая целиком: один вызов на все локали, без рук.
Дальше — два рубежа, которые оставлены человеку сознательно.

**Отбор по §4.** Машине доступна часть: локаль применилась, экран
рабочий, а не спиннер, в поле напечатан наш адрес — это утверждения
сценария, и они роняют прогон, а не пропускают кадр. Недоступно
главное: «в ролике чужой бренд», «выглядит прилично». Страница,
которая продаёт достоверность, не может показать кадр, которого никто
не видел.

**Файлы в репозитории.** Кадры лежат в `landing/public/illustrations/`
и попадают туда коммитом. Сервер коммитить не может, и это не
ограничение платформы, а тот самый рубеж, на котором плохой кадр
останавливают: git даёт просмотр, историю и откат одной командой.

Сделать последний шаг автоматическим технически можно — отдавать кадры
со ссылок Blob прямо со страницы. Тогда кадры обновлялись бы без
деплоя, а заодно исчезли бы: просмотр перед публикацией, бюджет веса,
оптимизация картинок Next и откат через git. Это отдельное решение с
ценой, а не мелкая доработка.

## Чего этот порядок не покрывает

- **Пересъёмку при смене интерфейса.** Кадры статичны: мастер
  перерисуют — они устареют молча. Шов на это завести нечем (сравнивать
  картинку не с чем), так что это пункт ручного чек-листа релиза.
- **Локали сверх снятых.** Пока локали нет в списке, она показывает
  схемы, и это корректное состояние, а не поломка: переключение
  поштучное.
- ~~**Стадию `page` двумя моментами.**~~ Закрыто 27.09.2026: два
  момента одной стадии — это два кадра между шагами одного съёмочного
  сценария (`waitFor` кадра страницы и `fill` поля), рук не нужно.
- **Годность кадра.** Прогон снимает что просили, а не что уместно:
  чужой бренд в ролике, жёлтая строка о ненастроенном окружении,
  спиннер вместо экрана — всё это отсеивает только §4 и только
  глазами.
